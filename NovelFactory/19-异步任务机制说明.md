# 异步任务机制说明

> 创建小程序、构建小程序、发布小程序 三个核心流程都是异步执行的。  
> 本文档说明它们的工作原理、前端如何感知任务进度和完成状态。

---

## 一、整体架构

```
前端 ──HTTP请求──> Controller ──返回taskId──> 前端
                      │
                      ▼ (异步)
               TaskQueueManager (任务队列)
                      │
                      ▼
              TaskExecutionService (任务执行)
                      │
                      ▼
         BuildTaskProcessor / PublishTaskProcessor
                      │
                      ▼ (实时推送)
              WebSocket (STOMP协议)
                      │
                      ▼
                    前端
```

**核心思路**: 接口立即返回 taskId，后端异步执行任务，通过 WebSocket (STOMP) 实时推送日志和状态给前端。

---

## 二、WebSocket 连接

### 连接地址
```
ws://<host>:<port>/ws   (SockJS)
```

### STOMP 消息代理
- 消息代理前缀: `/topic`
- 应用目标前缀: `/app`

### 订阅主题一览

| 主题 | 用途 | 消息格式 |
|------|------|----------|
| `/topic/build-logs/{taskId}` | 单个任务的构建/npm日志 | 纯文本(每行日志) |
| `/topic/batch-build-logs/{batchTaskId}` | 批量构建日志 | `{ "taskId": "xxx", "log": "日志内容" }` |
| `/topic/batch-build-status/{batchTaskId}` | 批量构建状态 | `{ "taskId": "xxx", "status": "running/completed/failed", "progress": 0-100 }` |
| `/topic/batch-publish-status/{batchTaskId}` | 批量发布状态 | 同上 |
| `/topic/novel-create-log/{taskId}` | 创建小程序日志 | `{ "timestamp": "HH:mm:ss", "message": "日志", "type": "info/success/error/processing/finish" }` |

## 三、创建小程序流程

### 3.1 流程概述

```
POST /api/novel-create/createNovelApp
        │
        ├─ 1. 校验: 同名同平台不允许重复
        ├─ 2. 创建任务: CreateNovelTaskManager.createTask() → taskId
        │     (同一时间只允许一个创建任务)
        ├─ 3. 立即返回 { "taskId": "uuid" }
        │
        └─ 4. CompletableFuture.runAsync 异步执行:
              ├─ 等待500ms (给前端时间订阅WebSocket)
              ├─ 数据库操作 (事务性, @Transactional)
              │   └─ 写入 novel_app / app_common_config / app_pay / app_ad 等表
              ├─ 本地代码文件操作
              │   └─ 生成 appConfig / deliverConfig / pages-xx.json 等配置文件
              ├─ 资源文件处理
              │   └─ 根据主题色生成资源文件
              └─ 完成/失败
```

### 3.2 前端如何知道完成

1. 调用接口拿到 `taskId`
2. 通过 WebSocket 订阅 `/topic/novel-create-log/{taskId}`
3. 监听消息，根据 `type` 字段判断:

| type | 含义 |
|------|------|
| `info` | 普通信息日志 |
| `processing` | 正在处理中 |
| `success` | 某步骤成功 |
| `error` | 出错了 |
| **`finish`** | **任务结束(固定消息: "Create Novel Finish")** |

4. **收到 `type=finish` 的消息即表示任务完成**（无论成功还是失败）
5. 如果之前收到过 `type=error`，说明创建失败；否则创建成功

### 3.3 并发控制

- `CreateNovelTaskManager` 使用 `AtomicReference` 保证同一时间只有一个创建任务
- 如果已有任务在运行，接口直接返回错误: "已有小说创建任务正在进行中，请稍后再试"

## 四、构建小程序流程

### 4.1 流程概述

```
POST /api/novel-build/build  (单个)
POST /api/novel-build/batch-build  (批量)
POST /api/novel-build/batch-build-test  (批量测试)
        │
        ├─ 1. 创建 TaskQueueItem，设置 taskType="build"
        ├─ 2. 加入 TaskQueueManager 队列
        ├─ 3. 立即返回 taskId / { batchTaskId, taskIds }
        │
        └─ 4. TaskQueueManager 异步处理:
              ├─ 判断正式/测试环境 → 进入对应队列
              ├─ 队列串行执行(同一环境同时只运行一个任务)
              ├─ 首个任务延迟5秒执行(等前端建立WebSocket)
              ├─ TaskExecutionService.executeBuildTask()
              │   └─ BuildTaskProcessor.process()
              │       └─ 执行shell命令(uni-app构建)
              │           └─ 实时读取stdout，推送到WebSocket
              └─ 完成后自动执行队列中下一个任务
```

### 4.2 前端如何知道完成

**单个构建**:
1. 订阅 `/topic/build-logs/{taskId}` 接收实时日志
2. 日志流结束 = 构建完成

**批量构建**:
1. 订阅 `/topic/batch-build-logs/{batchTaskId}` 接收所有子任务日志
2. 订阅 `/topic/batch-build-status/{batchTaskId}` 接收状态更新
3. 状态消息格式:

```json
{
  "taskId": "单个任务ID",
  "status": "running | completed | failed",
  "progress": 85,
  "description": "任务描述",
  "userId": 1,
  "username": "admin",
  "taskType": "build"
}
```

4. **当 `status` 变为 `completed` 或 `failed` 时，该任务完成**
5. 所有子任务都完成 = 批量构建完成

### 4.3 队列机制

- **正式环境队列** 和 **测试环境队列** 独立运行，互不影响
- 同一环境内串行执行，一个任务完成后自动取下一个
- 可通过 `GET /api/task-queue/statistics` 查询队列状态
- 可通过 `GET /api/task-queue/position?taskId=xxx` 查询排队位置

### 4.4 停止构建

- 单个: `GET /api/novel-build/stop?taskId=xxx`
- 批量: `GET /api/novel-build/stop-batch?batchTaskId=xxx`
- 原理: 中断执行线程 + 销毁子进程(Process.destroy)

## 五、发布小程序流程

### 5.1 流程概述

```
POST /api/novel-publish/publish  (单个)
POST /api/novel-publish/batch-publish  (批量)
POST /api/novel-publish/batch-preview-test  (批量预览测试)
        │
        ├─ 1. 校验参数(平台代码、appId、token等)
        ├─ 2. 创建 TaskQueueItem，设置 taskType="publish"/"preview"
        ├─ 3. 加入 TaskQueueManager 队列
        ├─ 4. 立即返回 taskId / { batchTaskId, taskIds }
        │
        └─ 5. TaskQueueManager 异步处理:
              ├─ 同构建一样的队列串行机制
              ├─ TaskExecutionService.executePublishTask()
              │   └─ PublishTaskProcessor.process()
              │       └─ 调用各平台CLI工具上传/预览
              │           ├─ 抖音: tt-ide-cli
              │           ├─ 微信: miniprogram-ci
              │           ├─ 快手: ks-cli
              │           └─ 百度: swan-toolkit
              └─ 完成后生成二维码文件(预览模式)
```

### 5.2 前端如何知道完成

**单个发布**:
1. 订阅 `/topic/build-logs/{taskId}` 接收实时日志
2. 日志流结束 = 发布完成

**批量发布**:
1. 订阅 `/topic/batch-publish-status/{batchTaskId}` 接收状态
2. 状态消息同构建，`status` 为 `completed` 或 `failed` 时完成

**获取预览二维码**:
- 单个: `GET /api/novel-publish/qrcode/{taskId}` → 返回PNG图片
- 批量: `GET /api/novel-publish/qrcode/batch/{batchTaskId}/{appId}` → 返回PNG图片

### 5.3 发布模式

| publishMode | 说明 |
|-------------|------|
| 无/默认 | 正式发布(上传代码) |
| `preview` | 仅预览(生成二维码，不上传) |

## 六、任务生命周期状态

```
pending → running → completed
                  → failed
                  → (被中断)
```

| 状态 | 说明 |
|------|------|
| `pending` | 在队列中排队等待 |
| `running` | 正在执行 |
| `completed` | 执行成功 |
| `failed` | 执行失败 |

每次状态变更都会:
1. 通过 STOMP WebSocket 推送状态更新消息
2. 任务完成后保存到数据库 `user_task` 表

## 七、前端接入示例 (伪代码)

```javascript
import SockJS from 'sockjs-client'
import { Client } from '@stomp/stompjs'

// 1. 建立WebSocket连接
const client = new Client({
  webSocketFactory: () => new SockJS('http://host:port/ws'),
  onConnect: () => {
    // 2. 订阅日志
    client.subscribe('/topic/build-logs/' + taskId, (msg) => {
      console.log('日志:', msg.body)
    })
    // 3. 订阅状态(批量任务)
    client.subscribe('/topic/batch-build-status/' + batchTaskId, (msg) => {
      const status = JSON.parse(msg.body)
      if (status.status === 'completed') {
        console.log('任务完成:', status.taskId)
      } else if (status.status === 'failed') {
        console.log('任务失败:', status.taskId)
      }
    })
  }
})
client.activate()

// 4. 发起构建请求
const res = await fetch('/api/novel-build/build?cmd=xxx', { method: 'POST' })
const taskId = res.data  // 拿到taskId后开始监听上面的WebSocket
```

## 八、总结对比

| 维度 | 创建小程序 | 构建小程序 | 发布小程序 |
|------|-----------|-----------|-----------|
| 接口 | `/api/novel-create/createNovelApp` | `/api/novel-build/build` | `/api/novel-publish/publish` |
| 异步方式 | CompletableFuture | TaskQueueManager队列 | TaskQueueManager队列 |
| 并发控制 | 全局只允许1个 | 同环境串行(正式/测试独立) | 同环境串行 |
| 日志主题 | `/topic/novel-create-log/{taskId}` | `/topic/build-logs/{taskId}` | `/topic/build-logs/{taskId}` |
| 完成标志 | `type=finish` 消息 | `status=completed/failed` | `status=completed/failed` |
| 支持批量 | 否 | 是(batch-build) | 是(batch-publish) |
| 数据库记录 | 创建过程中写入多表 | 完成后写入user_task表 | 完成后写入user_task表 |
