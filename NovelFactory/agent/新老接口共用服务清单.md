# 新老接口共用服务清单

## 1. 结论

对，新老接口在很多核心能力上，**本质上还是调用同一批服务 / Facade / Task Manager / 文件处理组件**。

差异主要在：

- Controller 入口不同
- 认证方式不同
- 权限注解不同
- 参数封装形式不同
- 审计和返回结构不同

所以最准确的说法是：

**入口层不同，业务内核大量复用。**

- `NovelAppCreationService`
- `CreateNovelTaskManager`

所以“怎么创建小程序”这件事，本质上还是同一套业务逻辑。

## 10. 为什么“共用服务”不等于“权限一致”

这是最容易误解的点。

虽然新老接口大量共用相同 service，但权限仍然可能不同，因为权限大多拦在：

- Filter
- SecurityConfig
- Controller 上的 `@PreAuthorize`
- 参数校验层

也就是说：

- “底层干活的人”是同一个
- 不代表“谁能给他派活”是一样的

所以正确结论是：

**新老接口大量共用服务，但不代表新老接口 permission 一致。**

---

## 11. 最终结论

如果你问“新老接口是不是两套完全不同系统”，答案是否定的。

更准确的结论是：

- 新老接口是两套不同的接入层
- 但底层大量复用相同的业务服务和任务执行组件

一句话总结：

**边界不同，内核大量相同。**
