# 新老接口权限对比

## 1. 结论

当前代码里，**新老接口权限不一致**。

更准确地说：

- 认证方式不一致
  - 老接口：主要走 `JWT`
  - 新 Agent 接口：主要走 `X-API-Key`

- 账号可用性校验已基本对齐
  - 网页登录会检查 `user.status`
  - Agent 的 `ApiKeyAuthenticationFilter` 现在也会检查 `user.status`

- 角色授权没有完全对齐
  - 老接口大量使用 `@PreAuthorize(...)`
  - 新 Agent 接口当前基本没有对应的角色注解

所以不能说“新老接口 permission 一样”。

| 维度 | 老接口 | 新 Agent 接口 |

## 5. 为什么会出现这种差异

原因不是 Spring Security 失效，而是新老接口设计目标不同：

- 老接口是网页后台接口
  - 直接在 Controller 上大量使用 `@PreAuthorize(...)`
  - 角色边界写得比较死

- 新接口是 Agent 接口
  - 先通过 `ApiKeyAuthenticationFilter` 认证
  - 可以识别出角色
  - 但当前 Controller 没有完整补齐和老接口一致的角色注解

所以当前状态是：

**能识别角色，不代表已经按角色做了同样的授权拦截。**

---

## 6. 当前已经对齐的部分

虽然角色授权还没完全对齐，但有一部分已经对齐：

### 6.1 账号状态

新老接口现在都会看 `user.status`：

- `status = 0`：允许
- `status = 1`：拒绝
- `status = 2`：拒绝

这意味着：

- 网页侧未审核账号不能登录
- Agent 侧未审核账号也不能继续使用 API Key

### 6.2 审计日志

新 Agent 接口和 API Key 管理接口已经补上了 `@OperationLog`，因此在审计日志层面已经有记录。

---

## 7. 还没对齐的部分

当前最核心的未对齐项是：

### 7.1 角色授权注解

老接口很多是：

```java
@PreAuthorize("hasAnyRole('ROLE_0','ROLE_1')")
```

或：

```java
@PreAuthorize("hasAnyRole('ROLE_0','ROLE_1','ROLE_2')")
```

而对应的 Agent 接口当前没有同等限制。

### 7.2 业务归属

老接口和新接口当前都没有真正把“创建人归属”落到业务主链路里，只是审计层有记录。

### 7.3 `PermissionInfo`

[PermissionInfo.java](/Users/nicolerli/nico_ai/NovelFactoryAI_async/NovelAppManagerServer/src/main/java/com/fun/novel/dto/PermissionInfo.java) 当前只是查询返回里的占位字段，不参与真实授权。

所以不能把它当成“新接口权限已经对齐”的证据。

---

## 8. 如果要做到真正一致，应该怎么改

原则很简单：

**让 Agent 接口的角色限制和对应老接口完全一致。**

建议映射：

| Agent 接口 | 应对齐老接口 | 建议角色 |
|------|------|------|
| `/api/agent/app/create` | `/api/novel-create/createNovelApp` | `ROLE_0, ROLE_1` |
| `/api/agent/build` | `/api/novel-build/build` | `ROLE_0, ROLE_1` |
| `/api/agent/publish` | `/api/novel-publish/publish` | `ROLE_0, ROLE_1` |
| `/api/agent/app/update` | `/api/novel-apps/update` | `ROLE_0, ROLE_1, ROLE_2` |
| `/api/agent/app/delete` | `/api/novel-apps/delete` | `ROLE_0, ROLE_1` |
| `/api/agent/app/list/query/detail` | 需结合老查询接口进一步统一 | 建议明确写出 |
| `/api/agent/task/{taskId}/status` | 需结合老任务查询口径统一 | 建议明确写出 |

实现方式不是改 API Key 机制，而是：

1. 保持 `ApiKeyAuthenticationFilter` 不动
2. 在 Agent Controller 上补 `@PreAuthorize(...)`
3. 按老接口的角色矩阵逐个对齐

---

## 9. 最终判断

当前系统里：

- 新老接口的**认证入口不同**
- 新老接口的**账号状态校验已经基本一致**
- 新老接口的**角色授权并不一致**

所以最终结论是：

**新老接口 permission 现在不一样。**

如果要真正一致，下一步要做的是：

**把 Agent 接口的 `@PreAuthorize` 按老接口规则补齐。**
