# 发布二维码获取机制

发布/预览任务完成后，二维码有两种获取方式，分别适用于网页端和脚本/Agent 调用场景。

---

## 概览

| 场景 | 获取方式 | 说明 |
|---|---|---|
| 网页端实时展示 | WebSocket 推送 | 发布过程中实时推送，前端监听后直接渲染 |
| 脚本 / Agent | HTTP 接口轮询 | 任务完成后调接口下载 PNG 文件 |

---

## 二维码的生成过程

各平台 CLI 工具执行发布/预览命令时，输出中包含二维码信息：

- **抖音**：输出包含 `二维码信息：https://...` 的日志行，后端解析 URL 并用 ZXing 编码成 PNG 图片保存到本地
- **快手 / 微信 / 百度**：CLI 工具直接生成二维码图片文件

生成的 PNG 文件保存在 `projectPath` 目录下，文件名按平台固定：

| 平台 | 文件名 |
|---|---|
| 抖音（mp-toutiao） | `tt_qrcode.png` |
| 快手（mp-kuaishou） | `ks_qrcode.png` |
| 微信（mp-weixin） | `wx_qrcode.png` |
| 百度（mp-baidu） | `bd_qrcode.png` |

---

## 方式一：WebSocket 实时推送（网页端）

发布过程中，后端通过 WebSocket 实时推送日志和状态：

**单个发布**：
```
/topic/publish-logs/{taskId}
```

**批量发布**：
```
/topic/batch-publish-logs/{batchTaskId}
/topic/batch-publish-status/{batchTaskId}
```

二维码生成成功时，推送的消息中包含二维码 URL（抖音）或成功状态，前端根据消息内容直接渲染二维码。

---

## 方式二：HTTP 接口下载（脚本 / Agent）

任务完成后，通过 HTTP 接口读取本地 PNG 文件返回：

**单个发布**：
```
GET /api/agent/publish/qrcode/{taskId}
```

**批量发布**：
```
GET /api/novel-publish/qrcode/batch/{batchTaskId}/{appId}
```

批量接口内部通过 `batchTaskId + appId` 找到对应的 `taskId`，再读取本地 PNG 文件返回，底层逻辑与单个发布一致。

**注意**：文件不存在时返回 HTTP 404，说明任务尚未完成或二维码尚未生成，需等待后重试。

---

## 两种方式的关系

网页端和脚本读取的是同一个本地 PNG 文件，只是获取时机和方式不同：

```
发布命令执行
    ↓
CLI 输出二维码信息
    ↓
后端保存 PNG 到 projectPath
    ├── WebSocket 推送 → 前端实时渲染
    └── PNG 文件落盘 → HTTP 接口按需读取
```
