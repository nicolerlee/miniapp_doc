# 前端接口切换计划

## 一、目标

前端部分核心操作（创建、删除、单个构建、单个发布）统一切到 Agent 接口。其他操作（编辑、批量构建/发布、版本号管理等）保持用老接口不动。

认证方式不变：网页用 JWT，Agent/脚本用 API Key，同一个接口两种认证都支持。

---

## 二、后端接口适配

### 2.1 AppListItemDTO 最小补字段方案

当前 `AppListItemDTO` 缺少 AppList.vue 依赖的多个字段。以下按必要性分级：

#### 必须补（不补会导致功能异常）

| 字段 | 类型 | 前端用途 | 不补的后果 |
|------|------|---------|-----------|
| tokenId | Integer | 编辑弹窗预填、表格列展示、编辑提交 | 编辑回填为空，提交丢字段 |
| cl | String | 搜索过滤条件、编辑弹窗预填、表单必填校验 | 搜索结果不全，编辑回填为空，保存时校验报错 |
| createTime | LocalDateTime | 表格列展示"创建时间" | 列显示为空 |
| updateTime | LocalDateTime | 表格列展示"更新时间" | 列显示为空 |

#### 建议补

| 字段 | 类型 | 前端用途 | 不补的后果 |
|------|------|---------|-----------|
| lastBuildTime | LocalDateTime | 表格列展示"最后构建时间" | 列显示为空 |

#### 不用补

| 字段 | 原因 |
|------|------|
| mainTheme / secondTheme | 存在 UI 配置表里，不在 `NovelApp` 实体中。老接口 `appLists` 返回的 `NovelApp` 里也没有这两个字段，前端虽然映射了但值一直是 `undefined`。不补不会比现在更差 |

#### 改名

| 当前名 | 改为 | 原因 |
|--------|------|------|
| `appId` | `appid` | 与老接口 `NovelApp` 实体一致，前端不用改 |

#### 改动清单

```java
// AppListItemDTO.java

// 1. appId 改名为 appid
private String appid;  // 原来是 appId

// 2. 新增 4 个必须字段
private Integer tokenId;
private String cl;
private LocalDateTime createTime;
private LocalDateTime updateTime;

// 3. 新增 1 个建议字段
private LocalDateTime lastBuildTime;

// 4. from() 方法补齐映射
public static AppListItemDTO from(NovelApp app) {
    // ... 原有字段 ...
    dto.setAppid(app.getAppid());             // 原来是 setAppId
    dto.setTokenId(app.getTokenId());         // 新增
    dto.setCl(app.getCl());                   // 新增
    dto.setCreateTime(app.getCreateTime());   // 新增
    dto.setUpdateTime(app.getUpdateTime());   // 新增
    dto.setLastBuildTime(app.getLastBuildTime()); // 新增
    return dto;
}
```

**最终结论：必须补 4 个字段 + 建议补 1 个字段 + 改名 1 个字段。Agent 脚本调用方同步改用 `appid`。**

### 2.2 Agent 列表接口响应格式差异

| 对比项 | 老接口 `/api/novel-apps/appLists` | 新接口 `/api/agent/app/list` |
|--------|----------------------------------|------------------------------|
| 返回结构 | `Map<String, List<NovelApp>>`（按平台分组） | `List<AppListItemDTO>`（扁平列表） |
| 分组 | 后端分组 | 无分组，前端自己按 `platform` 分组 |

## 三、前端接口地址替换

### 3.1 应用列表

| 文件 | 老接口 | 新接口 |
|------|--------|--------|
| `AppList.vue` | `GET /api/novel-apps/appLists` | `GET /api/agent/app/list` |
| `AutoBuild.vue` | `GET /api/novel-apps/appLists` | `GET /api/agent/app/list` |
| `BatchBuild.vue` | `GET /api/novel-apps/appLists` | `GET /api/agent/app/list` |
| `BatchBuildTest.vue` | `GET /api/novel-apps/appLists` | `GET /api/agent/app/list` |
| `AppListSelector.vue` | `GET /api/novel-apps/appLists` | `GET /api/agent/app/list` |
| `NovelSearchBody.vue` | `GET /api/novel-apps/appLists` | `GET /api/agent/app/list` |
| `PreviewByConfig.vue` | `GET /api/novel-apps/appLists` | `GET /api/agent/app/list` |
| `PreviewByApp.vue` | `GET /api/novel-apps/appLists` | `GET /api/agent/app/list` |

注意事项：
- 老接口返回 `Map<platform, List<NovelApp>>`，新接口返回 `List<AppListItemDTO>`
- 前端需要自己按 `platform` 字段做分组
- 字段名已统一为 `appid`，前端不用改

### 3.2 不能切换的页面

以下页面必须继续用老接口，因为依赖 Agent 接口没有的字段：

| 文件 | 继续用的老接口 | 原因 |
|------|--------------|------|
| `WeijuConfig.vue` (appManager) | `GET /api/novel-apps/appListsWithBusinessTypeAndPublicSwitch` | 依赖 `business_type`、`business_type_alias`、`public_switch`、`public_switch_alias` 等微距聚合字段，`AppListItemDTO` 没有这些字段 |
| `WeijuConfig.vue` (test) | 同上 | 同上 |
| `WeijuConfigDetail.vue` | 同上 | 同上 |

### 3.3 应用详情

| 文件 | 老接口 | 新接口 |
|------|--------|--------|
| `BatchBuildConfigStep.vue` | `GET /api/novel-apps/getByAppId` | `GET /api/agent/app/detail` |

注意：返回结构不同，前端取值逻辑需要改。
- 老接口返回 `Result<NovelApp>`，字段在 `res.data.deliverId`、`res.data.bannerId` 等顶层
- 新接口返回 `Result<NovelAppAggregateView>`，基础字段在 `res.data.baseConfig` 下面
- 前端需要把 `response.data.deliverId` 改为 `response.data.baseConfig.deliverId`，其他字段同理

### 3.4 删除应用

| 文件 | 老接口 | 新接口 |
|------|--------|--------|
| `AppList.vue` | `GET /api/novel-apps/delete?appId=xxx` | `DELETE /api/agent/app/delete?appId=xxx` |

注意：HTTP 方法从 GET 改为 DELETE。

### 3.5 创建应用

| 文件 | 老接口 | 新接口 |
|------|--------|--------|
| `AutoCreate.vue` | `POST /api/novel-create/createNovelApp` | `POST /api/agent/app/create` |

请求体格式一致，都是 `CreateNovelAppRequest`，无需改参数。

> 注意：AppList.vue 代码里残留了 `handleAddApp` + `POST /api/novel-apps/create` 的新增分支，但模板上没有按钮触发它，属于死代码。本次一并删除（`handleAddApp` 函数 + `handleSave` 中 `isEdit === false` 的创建分支）。

### 3.6 单个构建

| 文件 | 老接口 | 新接口 |
|------|--------|--------|
| `AutoBuild.vue` | `POST /api/novel-build/build?cmd=xxx` | `POST /api/agent/build` body: `{"cmd":"xxx"}` |

注意两处差异：
1. 请求参数：老接口 cmd 是 query param，新接口是 request body
2. 响应体结构不同：
   - 老接口返回 `Result<String>`，`res.data` 直接就是 taskId 字符串
   - 新接口返回 `Result<Map<String, String>>`，taskId 在 `res.data.taskId` 里
   - 前端 `res.data` 取 taskId 的地方必须改为 `res.data.taskId`，否则 WebSocket 日志订阅会坏掉

### 3.7 单个发布

| 文件 | 老接口 | 新接口 |
|------|--------|--------|
| `AutoPublish.vue` | `POST /api/novel-publish/publish` | `POST /api/agent/publish` |

请求体格式基本一致。

## 四、不切接口的部分

以下继续用老接口地址不动：

- **编辑应用**：`POST /api/novel-apps/update`（AppList.vue）
- **版本号管理**：`incrementVersions`、`updateVersion`、`batchUpdateVersion`
- **批量构建**：`/api/novel-build/batch-build`、`batch-build-test`
- **批量发布**：`/api/novel-publish/batch-publish`、`batch-preview-test`
- **停止构建/发布**：stop 相关接口
- **二维码获取**：`/api/novel-publish/qrcode/xxx`
- **构建产物列表**：`/api/novel-publish/list`
- **微距配置相关**：`appListsWithBusinessTypeAndPublicSwitch`

不需要改。日志推送是后端 Service 层通过 `SimpMessagingTemplate` 发的，跟调哪个 Controller 无关：

- 创建日志：`/topic/novel-create-log/{taskId}`
- 构建日志：`/topic/build-logs/{taskId}`

## 七、实施步骤

1. 后端 `AppListItemDTO` 补齐 5 个字段（tokenId、cl、createTime、updateTime、lastBuildTime）+ `appId` 改名为 `appid` + `from()` 方法更新
2. 应用列表页面切换（8 个文件，WeijuConfig 系列不切），AppList.vue 需改造分组逻辑
3. 创建切换：AutoCreate.vue 改地址；AppList.vue 删除 `handleAddApp` + 创建分支死代码
4. 删除切换：AppList.vue 改 HTTP 方法 GET → DELETE
5. 单个构建切换：AutoBuild.vue 改地址 + cmd 从 query param 改为 request body
6. 单个发布切换：AutoPublish.vue + PreviewQrCodePanel.vue 都改地址
7. 联调验证
8. 后端删除已废弃的老接口（见第九章）

预计工期：2-3 天

## 八、风险点

1. **列表接口返回格式差异**：老接口按平台分组，新接口是扁平列表，AppList.vue 的 `fetchAppList` 需要改造分组逻辑
2. **AppListItemDTO 字段补齐**：必须补 4 个字段（tokenId、cl、createTime、updateTime），建议补 1 个（lastBuildTime）。不补会导致 AppList.vue 搜索条件变少、编辑弹窗预填不完整、表格部分字段为空。mainTheme/secondTheme 不用补（老接口也没返回）
3. **AppList.vue 残留死代码**：`handleAddApp` + `POST /api/novel-apps/create` 创建分支没有模板入口触发，本次直接删除
4. **WeijuConfig 系列页面不能切**：依赖 `business_type`、`public_switch` 等微距聚合字段
5. **删除接口 HTTP 方法变化**：GET → DELETE
6. **构建接口两处差异**：cmd 从 query param 变成 request body，且响应体从 `res.data`（字符串）变成 `res.data.taskId`（Map），不改取值逻辑会导致 WebSocket 日志订阅坏掉
7. **应用详情返回结构变化**：老接口字段在顶层 `res.data.xxx`，新接口在 `res.data.baseConfig.xxx`，BatchBuildConfigStep.vue 取值逻辑需要改
8. **PreviewQrCodePanel.vue 发布入口**：公共组件也调了发布接口，需要一起切换，否则会出现"主页面走新接口，公共组件走老接口"的半切换状态
9. **appId → appid 改名影响**：Agent 脚本调用方（`agent-scripts/` 下的脚本）需要同步改用 `appid` 字段

---

## 九、切换完成后删除的老接口

前端切换完成并验证通过后，以下老接口不再有调用方，从后端删除：

| 老接口 | Controller | 被替代为 | 说明 |
|--------|-----------|---------|------|
| `POST /api/novel-create/createNovelApp` | NovelAppCreateController | `POST /api/agent/app/create` | 整个 Controller 可删除 |
| `POST /api/novel-apps/create` | NovelAppController | `POST /api/agent/app/create` | 死代码入口，前端已删除调用 |
| `GET /api/novel-apps/delete` | NovelAppController | `DELETE /api/agent/app/delete` | 删除方法 |
| `POST /api/novel-build/build` | NovelAppBuildController | `POST /api/agent/build` | 单个构建 |
| `POST /api/novel-publish/publish` | NovelAppPublishController | `POST /api/agent/publish` | 单个发布 |

> 注意：以下老接口仍有前端在用，不能删除：
> - `POST /api/novel-apps/update` — 编辑应用（AppList.vue）
> - `GET /api/novel-apps/appLists` — 白名单接口，小程序客户端在用
> - `GET /api/novel-apps/getByAppId` — 虽然 BatchBuildConfigStep.vue 切到了 Agent detail，但其他地方可能还在用，需确认
> - `GET /api/novel-apps/appListsWithBusinessTypeAndPublicSwitch` — WeijuConfig 系列页面在用
> - 批量构建/发布、停止、二维码等 — 仍在用
> - 版本号管理相关 — 仍在用
