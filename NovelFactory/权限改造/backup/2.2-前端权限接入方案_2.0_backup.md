# 前端权限接入方案

## 一、目标

前端只做两件事：
- 登录后拿到当前用户权限列表
- 根据权限列表控制菜单、页面数据和按钮显示

后端 `@RequirePermission` 是安全底线，前端权限控制只是体验优化。

---

## 五、UI 交互逻辑

- 管理员在用户管理页面为用户分配角色（下拉选择：默认用户 / 产品 / 研发 / 管理员）
- 角色切换后，用户的权限立即按 `sys_role_permission` 表生效
- 前端通过 `/api/admin/permission/my` 获取当前用户的权限列表，控制菜单和按钮的显示/隐藏
- 超级管理员（`type=-1`）前端直接展示全部功能，不查权限表

## 二、权限数据获取

### 2.1 登录后拉取权限

```js
const res = await request.get('/api/admin/permission/my')
// 返回 ['agent:app:read', 'ci:build:run', 'config:ui:write', ...]
localStorage.setItem('permissions', JSON.stringify(res.data))
```

### 2.2 封装判断函数

```js
// utils/permission.js
export function getPermissions() {
  return JSON.parse(localStorage.getItem('permissions') || '[]')
}

export function hasPermission(code) {
  return getPermissions().includes(code)
}

export function hasAnyPermission(codes) {
  const permissions = getPermissions()
  return codes.some(code => permissions.includes(code))
}
```

### 2.3 建议补充

- 退出登录时清空本地权限缓存
- 切换账号后重新拉权限，不复用旧账号缓存
- 403 时提示“无权限”而不是静默失败

## 三、前端控制原则

### 3.1 三档控制策略

| 级别 | 策略 | 适用模块 |
|------|------|---------|
| 菜单隐藏 | 没权限的人连入口都看不到 | 用户管理、数据库导出、代码同步、工具箱 |
| 按钮隐藏 | 页面能进能看，操作按钮按权限显示 | 应用列表、构建、发布、配置编辑页面 |
| 数据兜底 | 页面可进入，但接口按权限返回 403 | 详情页、任务页、配置页、用户管理页 |

### 3.2 原则

- 菜单权限控制只决定“看不看得到入口”
- 按钮权限控制只决定“能不能点操作”
- 真正的数据安全只依赖后端，不依赖前端隐藏

## 四、菜单级改动

### 4.1 适用权限

- 用户管理 / 权限管理：`admin:user:read`
- 数据库导出：`admin:db-export:read`
- 代码同步：`admin:code-sync:test:read` 或 `admin:code-sync:prod:read`
- 工具箱：`ops:toolbox:read`

### 4.2 路由守卫示例

```js
router.beforeEach((to, from, next) => {
  const requiredPermission = to.meta?.permission
  const requiredAnyPermission = to.meta?.anyPermission
  const noSinglePermission = requiredPermission && !hasPermission(requiredPermission)
  const noAnyPermission = requiredAnyPermission && !hasAnyPermission(requiredAnyPermission)
  if (noSinglePermission || noAnyPermission) {
    next('/')
    return
  }
  next()
})
```

### 4.3 路由 meta 建议

```js
{
  path: '/admin/users',
  component: UserPage,
  meta: { permission: 'admin:user:read' }
},
{
  path: '/admin/code-sync',
  component: CodeSyncPage,
  meta: {
    anyPermission: ['admin:code-sync:test:read', 'admin:code-sync:prod:read']
  }
}
```

## 六、页面数据层改动

### 6.1 应用列表与详情

- 需要 `agent:app:read`
- 没权限时：
  - 菜单可隐藏，也可保留空页面
  - 但接口返回必须由后端兜底 403

### 6.2 任务页

- 查看任务状态、日志、队列统计、队列位置统一依赖 `ci:task:read`

### 6.3 发布结果页

- 查看二维码、查看发布结果依赖 `ci:publish:read`

### 6.4 配置页

- 列表、详情、搜索条件加载用 `*:read`
- 创建、编辑、删除、启用等操作用 `*:write`

建议页面内部也分成两层判断：
- 进入页面前：判断是否有 `read`
- 渲染操作区：判断是否有 `write`

### 6.5 API Key 页面

- 查看列表依赖 `apikey:read`
- 创建按钮依赖 `apikey:create`
- 删除按钮依赖 `apikey:delete`

### 6.6 工具箱页面

- 查看调试信息、发版前检查依赖 `ops:toolbox:read`
- 清除运行中任务、手动触发队列依赖 `ops:toolbox:execute`

### 6.7 CodeSync 页面

- 页面入口：有 `admin:code-sync:test:read` 或 `admin:code-sync:prod:read` 任一权限即可进入
- 环境切换：
  - 切到测试环境时，列表、状态、日志请求要求 `admin:code-sync:test:read`
  - 切到正式环境时，列表、状态、日志请求要求 `admin:code-sync:prod:read`
- 操作按钮：
  - `pull / push / stash / restore-stash / switch-branch / delete-dist / install-npm / cancel-install-npm`
    - 测试环境按钮依赖 `admin:code-sync:test:execute`
    - 正式环境按钮依赖 `admin:code-sync:prod:execute`
  - `copy-to-test` 按钮单独依赖 `admin:code-sync:copy-to-test`
- `copy-status` 页面块只有同时具备 `admin:code-sync:test:read` 和 `admin:code-sync:prod:read` 时才显示

## 七、权限管理页面（用户管理页内）

用户管理页面中，每个用户行增加「角色」列和角色切换操作：

### 7.1 UI 布局

```
┌──────────────────────────────────────────────────────────────┐
│  用户名    │ 邮箱           │ 角色         │ 状态   │ 操作   │
├──────────────────────────────────────────────────────────────┤
│  张三      │ z@example.com  │ [研发 ▼]     │ 已通过 │ 审核 删除│
│  李四      │ l@example.com  │ [产品 ▼]     │ 已通过 │ 审核 删除│
│  王五      │ w@example.com  │ [默认用户 ▼] │ 待审核 │ 审核 删除│
└──────────────────────────────────────────────────────────────┘
```

### 7.2 角色下拉选项

| 选项 | 对应 type 值 | 说明 |
|------|-------------|------|
| 默认用户 | 2 | 只能查看，不能操作 |
| 产品 | 1 | 能创建应用、编辑配置、构建发布 |
| 研发 | 0 | 全部业务操作 + 运维 |
| 管理员 | -1 | 全部权限（超级管理员） |

### 7.3 交互逻辑

- 下拉切换角色后，调用 `PUT /api/admin/user/{userId}/role` 保存
- 保存成功后该用户下次请求即按新角色的权限生效
- 仅超级管理员可见此页面和操作
- 不能修改自己的角色（防止超管把自己降级）


---

## 八、前端实施步骤

1. 登录后调用 `/api/admin/permission/my`
2. 封装 `getPermissions / hasPermission`
3. 路由表补 `meta.permission`
4. 菜单组件按 `hasPermission` 控制入口显示
5. 页面按钮按 `hasPermission` 控制显示
6. 配置页拆成 `read` 与 `write` 两层控制
7. 任务页、发布结果页接入 `ci:task:read`、`ci:publish:read`
8. 403 统一错误提示处理
9. 用户管理页面增加角色下拉切换
10. 联调验证权限覆盖是否正确

---

## 九、注意事项

1. 前端权限控制不能替代后端鉴权
2. 白名单接口即使前端不展示，也仍然可能被直接访问
3. `config:ad:read`、`config:pay:read` 这类权限点当前后端还没有完全接入，前端先按设计预留
4. 切账号、刷新 token、退出登录时要同步刷新权限缓存
