# 后端权限拆分方案

## 一、目标

后端权限模型按 `资源 + 动作` 拆成 37 个权限点，覆盖全部 104 个需鉴权接口。共 119 个接口（104 需鉴权 + 1 已认证即可 + 14 白名单）。

目标只有两个：
- 权限点边界干净，读写不混
- Controller 注解、数据库权限定义、接口映射三者一致

---

## 二、权限模型设计

### 2.1 核心原则

- **应用数据的读操作**：需要 `agent:app:read`
- **配置模块操作**：按 `read / write` 拆分，例如 `config:ui:read`、`config:ui:write`
- **构建/发布操作**：按 `run / stop / read` 拆分，例如 `ci:publish:run`、`ci:publish:stop`、`ci:publish:read`
- **任务查询操作**：统一使用 `ci:task:read`
- **系统/研发高危能力**：按 `read / execute` 拆分；涉及环境的接口再补 `test / prod` 维度，例如 `ops:code-sync:test:read`、`ops:code-sync:prod:execute`
- **白名单接口**：无需认证，保持现状

新用户注册后默认授予：
- `agent:app:read`
- `apikey:read`
- `apikey:create`
- `apikey:delete`

### 2.3 为什么这样拆

- `read` 和 `write` 拆开后，可以直接做只读角色和编辑角色
- `run` 和 `stop` 拆开后，可以把执行任务和中断任务分给不同人
- `task:read` 单独抽出来后，任务查看能力不再和构建/发布写操作绑死
- `read` 和 `execute` 拆开后，系统类接口不会出现“能看状态的人顺带能执行危险动作”

判断标准只有一条：

> 如果你想授权“看”，但不想授权“改/停/执行”，现在做不到，那这个权限点就应该拆。

### 2.4 用户-权限关联表

```sql
CREATE TABLE sys_user_permission (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    permission_code VARCHAR(128) NOT NULL,
    UNIQUE KEY uk_user_perm (user_id, permission_code)
);
```

### 2.5 鉴权逻辑

1. 请求进来，认证通过（JWT 或 API Key）
2. AOP 拦截 `@RequirePermission("xxx")`
3. 从 `SecurityContext` 拿当前用户
4. 查 `sys_user_permission` 看是否有该 `permission_code`
5. 超级管理员（`type=-1`）跳过检查，直接放行
6. 没有 `@RequirePermission` 注解的接口，默认已认证即可访问

## 三、后端改动

### 3.1 新增文件

```text
annotation/RequirePermission.java     — 自定义注解
security/PermissionAspect.java        — AOP 拦截器
service/PermissionService.java        — 权限查询服务（带缓存）
mapper/SysPermissionMapper.java       — 权限表 Mapper
mapper/SysUserPermissionMapper.java   — 用户权限表 Mapper
entity/SysPermission.java             — 权限实体
entity/SysUserPermission.java         — 用户权限实体
controller/PermissionController.java  — 权限管理接口
```

### 3.2 权限管理接口

```text
GET    /api/admin/permission/my                — 查询当前用户自己的权限列表（所有已登录用户可调）
GET    /api/admin/permission/list              — 查询所有权限定义（仅超级管理员）
GET    /api/admin/permission/user/{userId}     — 查询指定用户的权限列表（仅超级管理员）
POST   /api/admin/permission/grant             — 给用户授权（仅超级管理员）
DELETE /api/admin/permission/revoke            — 撤销用户权限（仅超级管理员）
POST   /api/admin/permission/batch-grant       — 批量授权（仅超级管理员）
```

### 3.3 Controller 注解替换规则

- 应用数据读操作接口 → `agent:app:read`
- 应用写操作接口 → `agent:app:create / update / delete`
- 版本号接口 → `agent:app:version:update`
- 配置查询接口 → `config:*:read`
- 配置修改接口 → `config:*:write`
- 构建发起接口 → `ci:build:run`
- 构建停止/队列接口 → `ci:build:stop`
- 发布查询接口 → `ci:publish:read`
- 发布发起接口 → `ci:publish:run`
- 发布停止接口 → `ci:publish:stop`
- 任务状态/日志/队列接口 → `ci:task:read`
- 运维状态查看接口 → `ops:*:read`
- 运维执行类接口 → `ops:*:execute`
- 系统管理接口 → `admin:user:*`
- 工具接口 → `ops:toolbox:*`
- `code-sync` 接口是特例：同一路径根据 `testEnvironment` 动态校验 `test / prod` 权限；`/copy-to-test` 仍保留独立权限点，但归到测试环境分组
