# 支付逻辑梳理

> 适用项目：funNovel H5 小说阅读器  
> 更新时间：2026-03-04

---

## 一、整体架构

```
用户触发支付
    │
    ▼
UI 层（payment-dialog / payment-card / payment-view）
    │  调用
    ▼
usePay Hook（src/hooks/usePay.js）
    │  调用
    ▼
Pay 类（src/modules/mod_pay/index.js）
    │  根据平台选择
    ├──► h5Pay（src/modules/mod_pay/host/h5.js）
    └──► wxh5Pay（src/modules/mod_pay/host/wxh5.js）
              │  跳转工具
              ▼
         jumpLink.js（处理不同浏览器环境的跳转）
              │
              ▼
         transfer.vue（微信安卓端中转页）
```

## 二、支付商品类型

| 类型 | 字段标识 | goods_type | from | 说明 |
|------|----------|------------|------|------|
| 会员包 | `service_id` | `member` | `1` | 订阅会员，解锁全站内容 |
| 代币包 | `token_id` | `token` | `2` | 充值书币，按本/章消费 |
| 单本特惠 | `vod_id` | `vod` | `3` | 仅限投流(ad)渠道，购买单本书 |

## 三、支付方式

| 支付方式 | 说明 |
|----------|------|
| 普通支付（normal_pay） | 一次性支付，跳转支付宝完成 |
| 续费支付（renew_pay） | 连续包月自动续费，需签约，走 renewConfirm 确认 |
| 代币支付（tokenPay） | 直接用账户余额购买，无需跳转第三方 |

## 四、核心文件说明

### 4.0 两个宿主的差异（h5.js vs wxh5.js）

> 构建时通过 `#ifdef MP-WXH5` 条件编译选择宿主，运行时再按 UA + 系统分支。

**普通支付跳转决策树**

```
发起普通支付
│
├─ 构建包 = h5（抖音/快手/普通H5）
│   ├─ iOS     → location.href = pay_url  ✅ 直接跳支付宝
│   └─ Android → location.href = pay_url  ✅ 直接跳支付宝
│
└─ 构建包 = wxh5（微信H5）
    ├─ iOS     → uni.navigateTo(transfer.vue)  ⚠️ 不再直跳，走中转页自动跳转
    │               └─ transfer.vue onMounted → location.href = pay_url（用户无感知）
    └─ Android → triggerFileDownload()         ⚠️ 微信安卓屏蔽直跳
                    └─ 下载文件触发系统菜单
                        └─ 用户选择支付宝打开
                            └─ transfer.vue → location.href = pay_url
```

**续费支付跳转决策树**

```
发起续费支付
│
├─ 构建包 = h5（抖音/快手/普通H5）
│   ├─ iOS     → location.href = schemaUrl  ✅ 直接跳支付宝签约
│   └─ Android → location.href = schemaUrl  ✅ 直接跳支付宝签约
│
└─ 构建包 = wxh5（微信H5）
    ├─ iOS     → handleULinkJump()           ⚠️ 微信iOS不能直跳 schema
    │               └─ location.href = https://ulink.alipay.com/?scheme=...
    └─ Android → triggerFileDownload()       ⚠️ 微信安卓屏蔽直跳
                    └─ 下载文件触发系统菜单
                        └─ 用户选择支付宝打开
                            └─ transfer.vue → location.href = schemaUrl
```

## 五、完整支付流程

### 5.1 普通支付（会员包 / 代币包）

```
1. 拉取套餐
   usePay.getPayment(url, { cartoon_id, si })       → 会员包列表
   usePay.getTokenPayment(url, { si })               → 代币包列表

2. 用户选择套餐
   usePay.onTapPayment(item)                         → 记录 payment.sel

3. 发起支付
   usePay.toPay()
     → makePayParams()                               → 构造支付参数（含透传字段）
     → checkPayParamsValid()                         → 校验 gateway_id 是否存在
     → Pay.toPay(url, payParams)
         → Pay.createOrder(url, payParams)           → POST /v1/cartoon/pay
         → 回调 event: 'createOrder'
         → hostPay.normal.pay(result, ...)           → 跳转支付宝

4. 支付宝跳转
   H5：直接 location.href = pay_url
   WXH5：调用 jumpNormal() → 根据浏览器环境选择跳转方式
     - 微信iOS：wxh5.js 直接 uni.navigateTo 到 transfer 中转页，transfer onMounted 自动执行 location.href（不经过 jumpNormal）
     - 微信安卓：triggerFileDownload() → 中转页 transfer.vue → location.href

5. 用户完成支付，返回页面
   页面 onShow 触发 → isPageShowFromPay 变为 true
   → 显示 pay-confirm-dialog（询问是否支付成功）

6. 用户确认支付结果
   usePay.h5PayConfirmCallback(orderCode, state)
     → Pay.payStatusConfirm(url, { orderCode })      → 轮询 /v1/cartoon/orderstatus
     → 最多轮询 5 次，每次间隔 3s
     → 回调 event: 'payStatusConfirm'
       - confirmStatus: 'success'  → 刷新 VIP 信息，触发 pay-success
       - confirmStatus: 'pending'  → 超时未确认
       - confirmStatus: 'requestFail' → 请求失败
```

### 5.2 续费支付（连续包月）

```
1. 套餐 is_renew == 1 时走续费流程
2. gateway_id 从 pay_list 中取 alipay 对应的 gateway_id
3. 创建订单后调用 hostPay.renew.pay()
   wxh5 包 - 微信iOS：handleULinkJump() → https://ulink.alipay.com/?scheme=...
   wxh5 包 - 微信安卓：triggerFileDownload() → transfer.vue（显示"点我前往签约"按钮，用户手动点击跳转）
   h5 包（抖音/快手等）：直接 location.href = schemaUrl
4. 返回页面后检查 localStorage 中的 renew-order
   → 调用 renewConfirm(order_code, 'success')       → POST /v1/cartoon/renewconfirm
5. 页面初始化时也会检查 renew-order，自动补确认
```

### 5.3 代币直接购买（余额充足）

```
1. 检查 userData.vipInfo.account.tokens[0].balance >= novelPayInfo.tokens[0].now_price
2. 且书籍开启了 pay_method.cartoon.token === '1'
3. 直接调用 usePay.tokenToPay(url, payment)         → POST /v1/cartoon/tokenpay
4. 无需跳转第三方，直接返回结果
```

## 六、套餐展示逻辑

套餐展示由微距（weijuConfig）配置控制，最多展示 6 个：

```
if (非ad渠道 && 只配了 package_si)
    → 只展示会员包

else if (非ad渠道 && 只配了 coin_si)
    → 只展示代币包

else (都配了 / 都没配 / ad渠道)
    → 同时拉取代币包和会员包
    → priority_payment == 1：代币在前，会员在后
    → priority_payment != 1：会员在前，代币在后
    → ad渠道且有单本特惠(vod.now_price > 0)：单本特惠插在最前

兜底逻辑（H5 ad渠道拉不到套餐）：
    → 使用 AppConfig.doudiSi = "h5ad" 重新拉取
```

## 八、平台 × 系统跳转矩阵（jumpLink.js）

> 第一层：编译时条件编译选宿主（`#ifdef MP-WXH5`）  
> 第二层：运行时 UA 判断选跳转方式（`isWxBrowser` / `os`）

### 8.1 普通支付（jumpNormal）

| 宿主包 | 浏览器环境 | 系统 | 跳转方式 | 说明 |
|--------|-----------|------|----------|------|
| h5Pay（非微信H5包） | 任意 | iOS / Android | `location.href = pay_url` | 直接跳转支付宝 |
| wxh5Pay（微信H5包） | 微信浏览器 | iOS | `uni.navigateTo(transfer.vue)` → `location.href = pay_url` | wxh5.js 直接跳转 transfer 中转页，transfer onMounted 自动跳，用户无感知 |
| wxh5Pay（微信H5包） | 微信浏览器 | Android | `triggerFileDownload()` → transfer.vue | 微信安卓屏蔽直跳，走文件下载中转 |
| wxh5Pay（微信H5包） | 非微信浏览器 | iOS / Android | `location.href = pay_url` | 其他浏览器直接跳 |

### 8.2 续费支付（jumpRenew）

| 宿主包 | 浏览器环境 | 系统 | 跳转方式 | 说明 |
|--------|-----------|------|----------|------|
| h5Pay（非微信H5包） | 任意 | iOS / Android | `location.href = schemaUrl` | 直接跳转支付宝签约页 |
| wxh5Pay（微信H5包） | 微信浏览器 | iOS | `handleULinkJump()` → `ulink.alipay.com/?scheme=...` | 微信iOS用 ULink 绕过限制 |
| wxh5Pay（微信H5包） | 微信浏览器 | Android | `triggerFileDownload()` → transfer.vue | 同普通支付，走文件下载中转 |
| wxh5Pay（微信H5包） | 非微信浏览器 | iOS / Android | `location.href = schemaUrl` | 直接跳转 |

### 8.3 其他跳转（jumpDouyin / jumpAlipayMini / jumpKsMini）

| 函数 | 浏览器环境 | 系统 | 跳转方式 |
|------|-----------|------|----------|
| jumpDouyin | 抖音浏览器 | iOS / Android | `location.href = schemaV2Url` |
| jumpDouyin | 微信浏览器 | iOS | `location.href = linkV2Url` |
| jumpDouyin | 微信浏览器 | Android | `triggerFileDownload(schemaUrl)` → transfer.vue |
| jumpDouyin | 支付宝浏览器 | iOS / Android | `location.href = schemaUrl` |
| jumpAlipayMini | 微信浏览器 | iOS | `handleULinkJump(schemaUrl)` |
| jumpAlipayMini | 微信浏览器 | Android | `triggerFileDownload(queryUrl)` → transfer.vue |
| jumpAlipayMini | 非微信浏览器 | iOS / Android | `location.href = schemaUrl` |
| jumpKsMini | 微信浏览器 | iOS | 返回 `'showTip'`（不跳转，提示用户） |
| jumpKsMini | 微信浏览器 | Android | `triggerFileDownload(queryUrl)` → transfer.vue |
| jumpKsMini | 非微信浏览器 | iOS / Android | `location.href = schemaUrl` |

### 8.4 微信安卓中转机制（triggerFileDownload）

```
triggerFileDownload(targetUrl)
    │
    ├── 1. 构造下载地址：
    │      https://paps.funshion.com/v1/res/appresources?url=encodeURIComponent(targetUrl)
    │
    ├── 2. 动态创建 <a download="jump.doc"> 并触发点击
    │      → 微信安卓弹出"用其他应用打开"系统菜单
    │
    └── 3. 用户选择支付宝 → 支付宝打开 transfer.vue

targetUrl 即 transfer.vue 的页面地址：
    {protocol}//{host}/{BASE_URL}pages/transfer/transfer?url=双重encodeURIComponent(支付链接)&type=jumpNormal
```

**transfer.vue 自动跳转原理**

```
支付宝打开 transfer.vue
    │
    ├── onLoad：把 URL query 参数存入 params
    │     params.url = 双重encode的支付链接
    │     params.type = jumpNormal / jumpRenew / jumpDouyin ...
    │
    └── onMounted：检查 params.url 是否存在
          ├── 有 url → 立即执行 location.href = params.url  （自动跳，用户无感知）
          └── 无 url → 不自动跳，等用户手动点按钮

// 核心就这几行
onMounted(() => {
  if (params.url) {
    handleRedirect()        // 页面一加载完立即跳
  }
})
const handleRedirect = async () => {
  location.href = params.url  // 跳到实际支付链接
}
```

> `jumpAlipayMini` / `jumpKsMini` 的 targetUrl 直接拼入 query（没有 `url=` 前缀），所以 `params.url` 为空，不会自动跳，需要用户手动点按钮。

### 8.5 transfer.vue 中转页行为

> 自动跳转条件：`onMounted` 里判断 `params.url` 是否存在。  
> `getTransferPath` 对不同 type 的 url 拼接方式不同，决定了是否自动跳。

| type | url 参数 | onMounted 自动跳 | 显示按钮 | 备注 |
|------|---------|-----------------|---------|------|
| `jumpNormal` | ✅ 有 | ✅ 自动跳 | ❌ 隐藏按钮 | 链接只能消费一次，不能让用户重复点 |
| `jumpRenew` | ✅ 有 | ✅ 自动跳 | ✅ 显示"点我前往签约" | 自动跳同时也保留按钮兜底 |
| `jumpDouyin` | ✅ 有 | ✅ 自动跳 | ✅ 显示"前往抖音" | 自动跳同时也保留按钮兜底 |
| `jumpAlipayMini` | ❌ 无（queryUrl 直接拼入） | ❌ 不自动 | ✅ 显示"前往支付宝" | 必须用户手动点 |
| `jumpKsMini` | ❌ 无（queryUrl 直接拼入） | ❌ 不自动 | ✅ 显示"前往快手" | 必须用户手动点 |

## 九、支付回调事件

| event | 触发时机 | data 说明 |
|-------|----------|-----------|
| `createOrder` | 创建订单后 | `{ status: 'success'/'fail'/'fail-paid', result }` |
| `clickpay` | 跳转支付宝后 | `{ result: { order_code, payParams } }` |
| `payStatusConfirm` | 轮询订单状态后 | `{ confirmStatus: 'success'/'pending'/'requestFail', order_code }` |
| `checkPayParams_err` | 支付参数校验失败 | 无 |

`fail-paid`（retcode 1604）表示已购买过，此时关闭当前策略并刷新播放。

## 十一、注意事项

1. **支付防重**：`disableClickPay` 标志位防止重复点击；`payment.isPaying` 防止并发支付请求。
2. **订单持久化**：创建订单成功后写入 localStorage（`renew-order` / `normal-order`），页面初始化时检查并补确认，防止用户支付后未回调。
3. **代币充足自动隐藏支付**：onMounted 时检查余额，若代币充足且书籍支持代币购买，直接隐藏支付弹窗。
4. **H5 URL 标记**：跳转支付宝前在 URL 上添加 `isAlipayRedirect=true`，用于页面 onShow 时判断是否从支付宝返回。
5. **续费 gateway_id**：续费支付的 gateway_id 不从全局配置取，而是从套餐的 `pay_list` 中取 alipay 对应的值。
6. **口令/橙心推渠道**：`from == 'appfun'` 时 promotion 字段传空，不透传推广参数。

## 十二、微信 iOS 连包支付回跳处理

> 微信 iOS 连包（续费）支付的特殊之处在于：从支付宝签约页返回时，微信会**刷新整个页面**，走 `onLoad` 而非 `onShow`，因此不能依赖内存状态，必须依赖 `localStorage` 恢复订单上下文。

### 12.1 跳出去

```
wxh5.js pay()
│
├── 1. history.pushState 在当前 URL 追加 isAlipayRedirect=true
│
├── 2. 判断 is_renew == '1' → 调用 jumpRenew()
│      └── jumpLink.js: 微信 iOS → handleULinkJump(schemaUrl)
│            └── location.href = "https://ulink.alipay.com/?scheme=" + encode(schemaUrl)
│            （通过支付宝 ULink 绕过微信对 schema 的屏蔽）
│
└── 3. payCallback event:'clickpay' 触发
       └── usePay payCallBack_ 中将订单写入 localStorage:
             uni.setStorageSync('renew-order', { order_code, payParams, businessTAG })
```

**关键文件**：
| 文件 | 职责 |
|------|------|
| `modules/mod_pay/host/wxh5.js` | 判断续费 → 调用 jumpRenew |
| `modules/mod_pay/tool/jumpLink.js` | handleULinkJump：微信 iOS 专用 ULink 跳转 |
| `hooks/usePay.js` → `payCallBack_` | 订单持久化到 localStorage |

### 12.2 回来后（页面刷新 → onLoad）

```
页面刷新 → onLoad
│
├── 1. 调用 wxh5IosRenewConfirmDialog()（优先级最高，与普通订单互斥）
│      ├── 条件：AppConfig.is_wxh5 && AppConfig.os === 'ios'
│      ├── 从 localStorage 读取 renew-order
│      ├── 清除 URL 中的 isAlipayRedirect=true（history.replaceState）
│      ├── isShowPayConfirmDialog = true
│      └── storageOrder = order（缓存到内存变量）
│
├── 2. 页面继续加载小说内容...
│
├── 3. watch(media.sel.need_pay) 触发
│      └── need_pay === '1' && isShowPayConfirmDialog === true
│            ├── 根据 businessTAG 决定弹窗样式（Business11/12 用 yellow 样式）
│            └── payConfirmDialog.canShow = true → 弹出支付确认弹窗
│
├── 4. 用户点击弹窗按钮
│      └── onPayConfirmDialogCallback(event)
│            ├── 调用 payApi.h5PayConfirmCallback(order_code, state)
│            │     ├── 清除 localStorage 中的 normal-order（如有）
│            │     ├── state='confirm' → 轮询 5 次 /v1/cartoon/orderstatus（每次间隔 3s）
│            │     ├── state='cancel'  → 仅轮询 1 次
│            │     └── 调用 renewConfirm(order_code, state) → POST /v1/cartoon/renewconfirm
│            └── payConfirmDialog.canShow = false（关闭弹窗）
│
└── 5. 轮询结果回调（payCallBack_ event:'payStatusConfirm'）
       ├── confirmStatus='success' → 刷新 VIP 信息，触发 pay-success
       ├── confirmStatus='pending' → 超时未确认，上报错误
       └── confirmStatus='requestFail' → 请求失败，上报错误
```

### 12.3 兜底机制

在 `getChapterPayment()` 中，如果发现 `localStorage` 仍存在未处理的 `renew-order`，会主动调用 `renewConfirm(order_code, 'failed')` 做补偿确认，防止用户支付成功但未走确认流程导致订单遗漏。

```javascript
// readerPage.vue → getChapterPayment()
const order = uni.getStorageSync('renew-order')
if (order && order.order_code) {
  await payApi.renewConfirm(order.order_code, 'failed')
}
```

### 12.4 与普通支付回跳的区别

| 对比项 | 普通支付（normal） | 连包支付（renew） |
|--------|-------------------|------------------|
| localStorage key | `normal-order` | `renew-order` |
| 跳转方式 | `uni.navigateTo(transfer.vue)` → transfer 自动 `location.href` | `handleULinkJump()` → ULink 直跳支付宝签约 |
| 回来后生命周期 | 可能走 onLoad（页面刷新）或 onShow（页面恢复） | **始终走 onLoad**（页面刷新） |
| 判断入口 | `options.isAlipayRedirect` | `wxh5IosRenewConfirmDialog()`（不依赖 URL 参数，只看 localStorage） |
| 优先级 | 低（被连包拦截后不执行） | **最高**（onLoad 中最先判断，互斥） |
| 额外确认接口 | 无 | `POST /v1/cartoon/renewconfirm` |
| 轮询次数（确认） | 5 次 | 5 次 |
| 轮询次数（取消） | 5 次 | 1 次 |
