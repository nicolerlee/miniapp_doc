# funNovel H5 登录逻辑梳理

> 覆盖平台：微信H5（wxh5）、快手H5（ksh5）、抖音H5（tth5）

---

## 一、整体架构

项目采用**工厂模式 + 条件编译**的多平台登录架构：

```
CommonFunc.goH5Login()          ← 统一登录入口（页面调用）
    └── Account.xxxLogin()      ← 账户层（Account.js）
        └── userHookApi.xxx()   ← Hook层（useUser.js）
            └── loginApi.login(param, method)  ← 登录API层（mod_user/index.js）
                └── LoginHandler.login()       ← 平台处理器（host/tth5|ksh5|wxh5.js）
                    └── 平台授权 / 后端接口
```

**平台判断**（`src/appConfig/_host.js`，条件编译）：

| 编译标记 | host 值 | platform 值 |
|---------|---------|------------|
| `MP-TTH5` | `tth5` | `douyin` |
| `MP-KSH5` | `ksh5` | `douyin` |
| `MP-WXH5` | `wxh5` | `wx` |

**用户状态**：使用 Pinia（`src/store/user.js`）管理，持久化到 `localStorage`，key 为 `userInfo`。

## 二、抖音H5登录（tth5）

### 2.1 两种登录方式

抖音H5支持两种方式，由 `allow_web_login` 标志位决定：

| 方式 | 触发条件 | 特点 |
|------|---------|------|
| **JSBridge方式** | `allow_web_login == false`（默认） | 在当前页面内弹出授权，无页面跳转 |
| **Web重定向方式** | `allow_web_login == true` | 跳转到抖音授权页，回调后返回 |

---

### 2.2 JSBridge 登录流程

**入口**：`CommonFunc.goH5Login()` → `Account.ttH5Login()`

```
1. 调用 _ttH5GetSignature(url, { url: window.location.href, app_code })
   └── 请求后端签名接口：AppConfig.url.ttH5GetSignature + '/douyin'
   └── 返回：{ nonce_str, signature, url, timestamp }

2. 调用 _ttH5JsBridgeConfig(client_key, signature, timestamp, nonce_str, url)
   └── 调用抖音 JS SDK：tt.config(...)
   └── 等待 sdkReady 回调

3. 调用 _ttH5JsBridgeShowOpenAuth(client_key)
   └── 调用抖音 JS SDK：tt.showOpenAuth(...)
   └── 弹出授权弹窗，用户确认后返回 ticket

4. 用 ticket 作为 code，调用 _ttH5OpenidLogin(openid_login, { code, app_code })
   └── 请求后端：AppConfig.url.ttH5Login + AppConfig.platform（即 'douyin'）
   └── 返回用户信息 { user_id, token, open_id, ... }

5. Account.requestUserInfo(res.data)
   └── 调用 userInfo 接口获取完整用户信息
   └── 更新 Pinia store，持久化到 localStorage
   └── 触发 user-changed 事件
```

**关键参数**：
- `get_signature`：`AppConfig.url.ttH5GetSignature + '/douyin'`
- `openid_login`：`AppConfig.url.ttH5Login + AppConfig.platform`
- `client_key`：`AppConfig.clientKey || AppConfig.appid`

---

### 2.3 Web 重定向登录流程

**入口**：`CommonFunc.goH5Login()` → `Account.ttH5LoginRedirectTo()`

```
第一阶段：发起授权跳转
1. spliceCurrentUrl() 获取当前页面 URL（含 num 参数）
2. 构建抖音授权 URL：
   ${AppConfig.url.ttH5WebAuth}
     ?client_key=${client_key}
     &state=${encodeURIComponent('{"url": "${current_url}"}')}
     &response_type=code
     &scope=user_info
     &redirect_uri=${AppConfig.url.ttH5LoginCallback}
3. window.location.href 跳转到抖音授权页

第二阶段：回调处理（loginCallback.vue）
4. 抖音回调到 loginCallback 页面，携带 ?code=xxx&state=xxx
5. 解析 state 中的 redirect_url（原始页面地址）
6. 调用 ttH5OpenidLogin(code)
   └── 请求后端：AppConfig.url.ttH5Login + AppConfig.platform
   └── 返回用户信息

7. 登录成功后，3秒后跳回 redirect_url（原始页面）
```

**回调页面**：`src/pages/loginCallback/loginCallback.vue`

---

### 2.4 错误上报

每个关键步骤都有 `Report.login.login_err()` 上报，`parm5` 字段标识步骤：
- `ttH5GetSignature`：获取签名结果
- `jsBridgeConfig`：SDK 配置结果
- `jsBridgeShowOpenAuth`：授权弹窗结果
- `ttH5OpenidLogin`：openid 登录结果

## 三、快手H5登录（ksh5）

### 3.1 登录方式

快手H5只有**Web重定向**一种方式，流程相对简洁。

**入口**：`CommonFunc.goH5Login()` → `Account.ksH5LoginRedirectTo()`

### 3.2 完整流程

```
第一阶段：发起授权跳转
1. spliceCurrentUrl() 获取当前页面 URL（含 num 参数）
2. 构建快手授权 URL：
   https://open.kuaishou.com/oauth2/authorize
     ?app_id=${AppConfig.appid}
     &scope=user_info
     &response_type=code
     &redirect_uri=${encodeURIComponent(current_url)}
     &state=ks_auth
3. location.href 跳转到快手授权页

第二阶段：回调处理
4. 快手将 code 回调到 current_url（当前页面，带 ?code=xxx&state=ks_auth）
5. 页面检测到 URL 中有 code 参数，调用 Account.ksH5OpenidLogin(code)
6. 调用 _ksH5OpenidLogin(AppConfig.url.ksH5Login, { code, app_code })
   └── 请求后端：AppConfig.url.ksH5Login
   └── 若返回 data 为空对象，则视为失败
   └── 成功返回用户信息

7. Account.requestUserInfo(res.data)
   └── 更新 Pinia store，持久化到 localStorage
   └── 触发 user-changed 事件
```

**注意**：快手回调直接回到原页面（`redirect_uri = current_url`），不经过独立的回调页面。

## 四、微信H5登录（wxh5）

### 4.1 登录方式

微信H5采用**后端代理授权**方式，前端只负责重定向，授权逻辑完全由后端（波塞冬接口）处理。

微信H5有两种登录入口：
- **普通业务页面**（readerPage / userInfo）：`CommonFunc.goH5Login()` → `Account.wxH5LoginRedirectTo()`，授权完成后回调到原页面
- **wxAuthPage 广告中间页**：专用于广告投放链路，授权完成后需额外查广告回调接口拿阅读页参数

### 4.2 完整四跳流程

**第一跳：前端 → 波塞冬**

```
1. spliceCurrentUrl() 获取当前页面 URL（含 num 参数）
2. 构建波塞冬授权 URL：
   https://puser.funshion.com/v2/oauth/wxpublicno_silence
     ?u=${encodeURIComponent(encodeURIComponent(current_url))}   ← 双重编码的回调地址
     &app_code=${AppConfig.app_code}
     &pt=${AppConfig.app_code}
3. location.href 跳转到波塞冬
```

**第二跳：波塞冬 → 微信（302重定向）**

波塞冬收到请求后立即 302 到微信官方授权页：
```
https://open.weixin.qq.com/connect/oauth2/authorize
  ?appid=wx09914a1124efa672          ← 公众号 appid（波塞冬持有）
  &redirect_uri=http://puser.funshion.com/v2/oauth/callback/wxpublicno_silence
      ?pt=${app_code}&u=${current_url}
  &response_type=code
  &scope=snsapi_userinfo             ← 会弹出微信授权确认页，用户需点击同意
  &state=STATE
  #wechat_redirect
```

> 注意：scope 是 `snsapi_userinfo`，**会弹出授权确认页**，并非完全静默。

**第三跳：微信 → 波塞冬 callback**

用户授权后，微信将 code 回调到 `redirect_uri`：
```
http://puser.funshion.com/v2/oauth/callback/wxpublicno_silence
  ?pt=wx_h5_xingchennovel
  &u=https://novelwxxc.fun.tv/...（原始页面地址）
  &code=微信返回的临时code
```
波塞冬服务端用 code 换取 openid，完成登录，生成 `user_id + token + open_id + union_id`。

**第四跳：波塞冬 → 前端原始页面**

波塞冬将登录结果拼到 `u` 参数指定的原始页面 URL 上，302 回跳：
```
https://novelwxxc.fun.tv/wx/xingchen/pages/readerPage/readerPage
  ?cartoon_id=3395821&num=4&...（原业务参数保留）
  &user_id=xxx&token=xxx&open_id=xxx&union_id=xxx&code=200   ← 登录结果
```

### 4.3 普通业务页面的回调处理

`readerPage.vue` / `userInfo.vue` 在 `onLoad` 中调用 `checkWxAuthBack(options)`：

```
1. 检测 options 中是否有 user_id + token + open_id
2. 调用 Account.processWxH5AuthCallback(options)
   ├── 检查 options.code 是否为 '200'，非 200 直接 return { success: false }
   ├── 调用 wxH5OpenidLogin(user_id, token, open_id)
   │     └── 直接写入 Pinia store，无需额外接口调用
   ├── 登录成功后把 union_id 写入 localStorage（_userInfo.union_id）
   └── 清理 URL 参数（user_id/token/open_id/code/union_id）
       window.history.replaceState({}, '', newUrl)  ← 无感知替换 URL
```

### 4.4 wxAuthPage 广告中间页的处理

wxAuthPage 是广告投放专用页面，除登录外还需查广告回调接口拿阅读页参数。详见 `doc/wxAuthPage业务时序图.md`。

**onLoad 三种情况**：

| 情况 | 触发条件 | 处理 |
|------|----------|------|
| 情况0 | 已登录 + localStorage 有 union_id | 直接查广告回调接口跳阅读页 |
| 情况1 | URL 带 union_id+user_id+token+open_id | 登录 + 存 union_id + 查接口跳阅读页 |
| 情况2 | 以上都不满足 | 展示授权引导页，等待用户点击授权 |

**关键参数**：
- `auth_url`：`AppConfig.url.wxH5Auth`（即 `https://puser.funshion.com/v2/oauth/wxpublicno_silence`）
- `u`：当前页面 URL，**双重 encodeURIComponent 编码**
- `pt` / `app_code`：渠道标识，如 `wx_h5_xingchennovel`

**与其他平台的区别**：
- 微信授权由波塞冬后端全程代理，前端不直接接触微信 OAuth
- 登录结果通过 URL 参数回传，前端读取后立即用 `replaceState` 清除，避免 token 残留在地址栏
- 不需要独立的回调页面，直接在业务页面处理
- `union_id` 授权成功后持久化到 localStorage，下次进 wxAuthPage 可跳过授权直接跳阅读页

## 五、登录后公共流程

三个平台登录成功后，都会执行以下公共流程：

```
Account.requestUserInfo(data)
    └── userHookApi.requestUserInfo(data)
        └── user.requestUserInfo({ url: AppConfig.url.userInfo, data, app_code })
            └── 请求 userInfo 接口，获取完整用户信息
            └── 写入 Pinia store（_userInfo）
            └── 持久化到 localStorage（key: userInfo）

Account.getDarenIdentiyInfo(true)
    └── 查询达人身份（AppConfig.url.getDarenIdentity）

Events.emit('user-changed', userInfo)
    └── 触发全局用户变更事件
    └── Account.onUserChanged() 中会刷新 VIP 权益信息
```

**Token 刷新**（`Account.updateToken`）：
- 触发时机：应用启动时，已登录状态下
- 刷新条件：距上次刷新超过 10 天
- 接口：`AppConfig.url.isLogin`
- 若 token 已过期（接口返回非 200），自动调用 `Account.logout()` 并提示重新登录

## 六、三平台对比

| 对比项 | 微信H5（wxh5） | 快手H5（ksh5） | 抖音H5（tth5） |
|--------|--------------|--------------|--------------|
| 授权方式 | 后端代理（波塞冬） | 前端重定向 | JSBridge 或前端重定向 |
| 是否需要 SDK | 否 | 否 | 是（抖音 JS SDK） |
| 回调页面 | 原页面 / wxAuthPage | 原页面 | 独立回调页（loginCallback） |
| 前端获取 code | 否（后端处理） | 是 | 是（ticket 或 code） |
| 登录接口调用 | 无（后端直接返回 token） | `ksH5Login` | `ttH5Login + platform` |
| 处理器文件 | `host/wxh5.js` | `host/ksh5.js` | `host/tth5.js` |
| 登录方法标识 | `wxAuth` | `ksAuth` | `js_bridge` / `web` |
| union_id 持久化 | 是（存 localStorage，供 wxAuthPage 情况0使用） | 否 | 否 |
| 广告中间页 | wxAuthPage（情况0/1/2） | 无 | 无 |
