# 渠道参数解析

## 问题背景

链接示例：
```
pages/mediaPage/mediaPage?mid=1118553&eid=13641043&coopCode=ad&microapp_id=wx166ab9112eb80702&popularizeId=funys&si=13024622&promotion_code=jlgg&promotion_ad_id=220690107&source=h5_gzh
```

该链接为**微信公众号投流渠道**（`coopCode=ad` + `source=h5_gzh`），对应业务策略63。

**现象**：小程序切到后台，再拉到前台，`jlgg_wx/wxh5adclick` 请求没有带上渠道参数（`si`、`promotion_code`、`source`、`popularizeId`、`microapp_id` 等）。

---

## 排查过程

### 1. 渠道参数本身没有丢失

切后台再回前台不触发 `onLoad`，内存中的 `vars.coopObj` 不会被清除，渠道参数本身是完好的。

### 2. `wxh5adclick` 请求参数的构造逻辑

`report.js` 中 `wxh5adclick` 函数：

```js
async wxh5adclick(prptChannel) {
  // ...
  const appOnShowParam = common.getAppOnShowParam();
  const options = appOnShowParam?.options || {};
  const { promotion_ad_id, callback } = reportParam.getReportParam();
  const basicParam = { union_id, app_code, promotion_ad_id, _callback_: callback, fudid };
  const submitParams = { ...options.query || {}, ...basicParam };  // ← 问题所在
  this.request({ url, data: submitParams, method: 'GET' });
}
```

### 3. 根本原因

`options.query` 来自 `common.getAppOnShowParam()`，内部调用 `uni.getEnterOptionsSync()`。

**`uni.getEnterOptionsSync()` 返回的是最近一次"进入"小程序的参数。** 切后台再回前台，这次进入的是微信播放器插件路径，query 为空：

```js
// App Show 时 launchOpt：
{
  path: "__plugin__/wx94a6522b1d640c3b/pages/playlet/playlet",
  query: {},   // ← 空的
  scene: 1000
}
```

所以 `options.query` 展开后是 `{}`，`source`、`si`、`promotion_code`、`popularizeId`、`microapp_id` 全部丢失，`wxh5adclick` 请求缺少渠道参数。

## 修复方案

### 核心思路

在 `onLaunch` 时将原始 query 保存到 `bus.launchQuery`，整个生命周期只写一次，不受切后台影响。`wxh5adclick` 直接使用这份数据。

### 改动一：`src/App.vue`

`onLaunch` 时无条件保存原始 query：

```js
// 修改前
if (!options.query) options.query = {}
if (!uni.canIUse('getEnterOptionsSync')) {
  bus.onLaunchQuery = options.query
}

// 修改后
if (!options.query) options.query = {}
bus.launchQuery = options.query  // 保存首次启动的原始参数，不受切后台影响
if (!uni.canIUse('getEnterOptionsSync')) {
  bus.onLaunchQuery = options.query
}
```

> `bus.onLaunchQuery` 是给 `getAppOnShowParam` 在不支持 `getEnterOptionsSync` 时的兜底，不能直接复用，需要新增 `bus.launchQuery` 字段。

### 改动二：`src/sdk/modules/report/report.js`

`wxh5adclick` 使用 `bus.launchQuery` 替代 `getAppOnShowParam().options.query`：

```js
// 修改前
const appOnShowParam = common.getAppOnShowParam();
const options = appOnShowParam?.options || {};
const { promotion_ad_id, callback } = reportParam.getReportParam();
const basicParam = { union_id, app_code, promotion_ad_id, _callback_: callback, fudid };
const submitParams = { ...options.query || {}, ...basicParam };

// 修改后
const launchQuery = bus.launchQuery || {};
const { promotion_ad_id, callback } = reportParam.getReportParam();
const basicParam = { union_id, app_code, promotion_ad_id, _callback_: callback, fudid };
const submitParams = { ...launchQuery, ...basicParam };
```

`basicParam` 覆盖 `launchQuery` 中的同名字段，确保 `promotion_ad_id`、`_callback_` 使用 `reportParam` 中最新的值。

## 补充说明

### `reportParam.getReportParam()` 包含的字段

`reportParam` 是中间处理层，字段在解析时按需写入，完整 key 列表：

**渠道相关（切页面时会 reset）：**
`source`、`callback`、`si`、`promotion_ad_id`、`promotion_code`、`promotion_thirdad_id`、`x_mid`、`x_eid`、`videoid`、`taskid`、`expert_open_id`、`cm_id`、`pt_finderid`、`pt_promotionid`、`allocate_id`、`saas_id`、`third_account_id`、`third_maccount_id`、`third_set_id`

**其他持久化字段：**
`ctime`、`url`、`osi`、`mid`、`eid`、`is_vip`、`m_shikan`、`e_shikan`、`deliver`、`shikan`、`is_inspiread`、`is_vip_profile`、`channel`、`is_vip_policy`、`unlock_type`、`tv_unlock_part`、`ad_ok`、`original_is_vip`、`from_block`

### 为什么不用 `reportParam` 直接替代

`reportParam` 是中间参数，字段较多且包含业务状态字段（`is_vip`、`mid`、`eid` 等），直接展开到 `wxh5adclick` 请求会造成参数污染。原始 query 语义更清晰，只包含进入时的链接参数。

### `uni.getEnterOptionsSync()` 的行为

| 场景 | 返回值 |
|------|--------|
| 冷启动 | 完整的启动参数，包含所有 query |
| 切后台再回前台（微信播放器插件） | `{ path: "__plugin__/...", query: {}, scene: 1000 }` |
| 切后台再回前台（普通页面） | `{ path: "pages/...", query: {}, scene: 1000 }` |
