# 渠道参数解析全流程

## 概述

渠道参数贯穿小程序整个生命周期，涉及两套独立的数据结构：

| 数据结构 | 模块 | 作用 |
|---------|------|------|
| `vars.coopObj` | `share.js` | 渠道身份识别，决定业务策略、支付逻辑、上报格式 |
| `vars.reportParam` | `reportParam.js` | 上报参数，随每次请求携带 |

两套数据在 `onLaunch` 时分别初始化，互相独立，但都来源于同一份原始 query。

---

## 一、渠道类型识别

### 1.1 渠道分类

```
coopClient 枚举（share.coopClient）：
  fun         风行自有渠道
  appfun      App 内嵌渠道
  ad          投流渠道（touliu）
  h5ad        H5 投流渠道（公众号投流）
  sphrw       微信视频号渠道（wxchannel）
  sph_cps     视频号 CPS 渠道
  doutuimao / tuixiaoguo / xingyao / ...  第三方渠道
```

### 1.2 渠道识别入口参数

不同渠道通过不同的 URL 参数组合来识别：

| 渠道类型 | 识别条件 | 示例 |
|---------|---------|------|
| H5 投流渠道 | `coopCode=ad && source=h5` | 公众号跳小程序投流 |
| 第三方渠道 | `coopCode` 在第三方名单中 | `coopCode=doutuimao` |
| 风行渠道（coopCode 模式） | `coopCode` 有值 + `coop_main/coop_appid/coop_expert` 齐全 | 内部分发 |
| 风行渠道（coop_client 模式） | `coop_main` + `coop_client` 均有值 | 内部分发 |
| 分享链接 | `entrance` 以 `share` 开头 | 用户分享 |
| 视频号 | `wxExportId` 有值 | 视频号跳转 |

> **注意**：`source=h5_gzh` 是公众号投流的实际值，但 `mountInputIsValid` 中判断条件是 `source === 'h5'`，两者不匹配，导致该渠道走 `valid=false` 分支，`coopObj` 不会被正确赋值。`isOfficialAccountClient()` 通过兜底逻辑（读 `getAppOnShowParam().query`）来识别该渠道。

## 二、冷启动解析流程

### 2.1 App.vue `onLaunch`

```
onLaunch(options)
  │
  ├─ bus.launchQuery = options.query          // 保存原始启动参数（不受切后台影响）
  ├─ bus.onLaunchQuery = options.query        // 仅在不支持 getEnterOptionsSync 时赋值
  │
  ├─ share.init({ cb: { onCoopChanged, onCoopUpdate } })
  │    └─ 注册渠道变化回调
  │
  ├─ share.parseCoopFromStorage()             // ① 从 storage 恢复上次的渠道参数
  │
  ├─ share.parseCoopFromParams(options.query) // ② 解析本次启动的渠道参数
  │    └─ 跳过条件：微信场景码（scene）/ 播放器插件路径
  │
  ├─ reportParam.loadFromStorage()            // ③ 从 storage 恢复上报参数
  │
  └─ reportParam.updateParam({ user_vip })    // ④ 更新用户 vip 状态
```

### 2.2 mediaPage.vue `onLoad`

```
onLoad(query)
  │
  ├─ options = query                          // 保存页面参数到模块级变量
  │
  ├─ [微信场景码] common.parseWxScene(options) // 解析场景码，更新 options
  │
  └─ share.parseCoopFromParams(options)       // 再次解析渠道参数（覆盖 onLaunch 的结果）
```

> `mediaPage.onLoad` 中的 `parseCoopFromParams` 会覆盖 `onLaunch` 中的解析结果，以页面实际参数为准。

## 三、`share.parseCoopFromParams` 详解

这是渠道参数解析的核心函数，写入 `vars.coopObj`。

```
parseCoopFromParams(params)
  │
  ├─ 如果 params.innerfrom 存在 → 直接返回，不解析（内部跳转不改变渠道）
  │
  ├─ mountInputIsValid(params)               // 判断渠道有效性
  │    ├─ coopCode=ad && source=h5  → h5ad 渠道，valid = microapp_id && popularizeId
  │    ├─ coopCode 在第三方名单     → 第三方渠道，valid = microapp_id && popularizeId
  │    ├─ coopCode 有值             → 风行渠道，valid = coop_main && coop_appid && coop_expert
  │    ├─ coop_main && coop_client  → 风行渠道，valid = true
  │    ├─ entrance 以 share 开头   → 分享渠道，valid = true
  │    ├─ wxExportId 有值           → 视频号渠道，valid = true
  │    └─ 其他                      → { valid: false }
  │
  ├─ [valid=true] parseCoopParams(checkResult, options)
  │    ├─ 构建 vars.coopObj.param（coop_main/coop_client/coop_expert/coop_appid/...）
  │    ├─ [投流渠道] 额外写入 si/callback/promotion_ad_id/promotion_code/promotionid
  │    ├─ [投流渠道] 检查 adStore 缓存（getAndCheckAdStore），同媒体未过期则用缓存
  │    ├─ [投流渠道] 写入 share-coop storage，附带过期时间（promotion_pt / 3698 小时）
  │    ├─ [第三方渠道 region=coop_code] 写入 share-coop storage
  │    ├─ [新渠道 region=coop_client] 清空 share-coop storage
  │    └─ vars.coopObj.mountParams = options  // 保存原始参数
  │
  ├─ [valid=false]
  │    └─ vars.coopObj = { mountParams: {}, param: {}, promotion: {} }  // 清空！
  │
  ├─ [投流渠道] 更新 share-osi storage（首次写入 si）
  │
  └─ checkIfMountChannelChanged()            // 检测渠道是否变化，触发回调
```

### 3.1 `vars.coopObj` 结构

```js
vars.coopObj = {
  param: {
    coop_main,      // 渠道主标识
    coop_client,    // 渠道客户端标识（对应 share.coopClient 枚举）
    coop_expert,    // 达人/推广者 ID（对应 popularizeId）
    coop_appid,     // 小程序 appid（对应 microapp_id）
    client,         // 同 coop_client
    region,         // 'coop_code' 或 'coop_client'，标记参数来源格式
    entrance,       // 入口标识（shareXXX 格式）
    source,         // 来源标识（如 h5_gzh）
    is_from,        // 挂载来源标记
    // 仅投流渠道有：
    si,             // 投流 session id
    callback,       // 回传 id（gdt_vid/clue_token/clickid 等）
    promotion_ad_id,
    promotion_code,
    promotionid,    // 对应 promotion_thirdad_id
  },
  mountParams: {},  // 原始 options 的完整拷贝（valid=true 时才有值）
  promotion: {      // 创建订单用
    coop, appid, expert
  },
  isScan: false,    // 是否扫码进入
}
```

## 四、`share.parseCoopFromStorage` 详解

在 `onLaunch` 时先于 `parseCoopFromParams` 执行，从 storage 恢复上次的渠道参数。

```
parseCoopFromStorage()
  │
  ├─ 读取 share-coop storage → share.coopStore
  │
  ├─ [华影阁品牌 + 投流渠道 + 首页路径] → 清空 coopObj 和 storage
  │
  ├─ [投流渠道过期检查] checkAdStoreExpired()
  │    └─ 过期 → 清空 storage，coopParam = {}
  │
  ├─ 读取 share-si storage
  │    └─ [投流渠道 + coopParam 缺少 si] → 补充 si
  │
  ├─ [抖音] 读取 share-clickid storage
  │    └─ [投流渠道 + coopParam 缺少 callback] → 补充 callback
  │
  └─ vars.coopObj = { param: coopParam }
```

> `parseCoopFromStorage` 只恢复 `param`，不恢复 `mountParams`。

## 五、`reportParam.parseReportParam` 详解

写入 `vars.reportParam`，用于所有上报请求的公共参数。

```
parseReportParam(options, extraParam)
  │
  ├─ [extraParam.resetVideoId=true] resetBeforeParse()
  │    └─ 清除 resetKeys 中的字段（source/si/callback/promotion_ad_id/promotion_code 等）
  │
  ├─ 遍历 reportKey，从 options 中提取对应字段
  │    └─ parseKeyMap 处理字段名映射（如 x_mid←mid，callback←clue_token 等）
  │
  ├─ procCallback(options) 处理 callback 字段
  │    ├─ 微信：优先 gdt_vid(txgdt) > qz_gdt(txgdt) > clue_token(jlgg) > trackid
  │    ├─ 抖音：clickid
  │    └─ 快手：callback
  │
  ├─ [si 有值 且 osi 无值] → osi = si
  │
  └─ save2Storage()：将 osi 写入 share-osi storage
```

### 5.1 `resetBeforeParse` 触发条件

`extraParam.resetVideoId = true` 时触发，清除以下字段：

```
source, callback, si, promotion_ad_id, promotion_code, promotion_thirdad_id,
x_mid, x_eid, videoid, taskid, expert_open_id, cm_id,
pt_finderid, pt_promotionid, allocate_id, saas_id,
third_account_id, third_maccount_id, third_set_id
```

触发场景：
- `App.vue onShow`：`launchOpt.path.includes('/mediaPage')` 时
- `playerManager.initMedia`：始终传 `{ resetVideoId: true }`

## 六、`onShow` 时的处理

### 6.1 App.vue `onShow`

```
onShow(launchOpt)
  │
  ├─ 更新 appConfig.scene
  ├─ 检查 CP 是否变化
  │
  ├─ extraParam = { resetVideoId: path.includes('/mediaPage') }
  │
  ├─ [微信前后台切换：query=={} ] 或 [抖音 showFrom=0]
  │    └─ 跳过 reportParam.parseReportParam（不解析上报参数）
  │
  ├─ [其他情况]
  │    └─ reportParam.parseReportParam(launchOpt.query, extraParam)
  │
  ├─ common.keepAppOnShowParam(launchOpt)
  │    └─ 更新 bus.onShowQuery = { query, showFrom, path }
  │
  └─ share.init({ config: { scanScene, scene, appid } })
```

### 6.2 mediaPage.vue `onShow`

```
onShow()
  │
  └─ 仅打 log，不做任何参数解析
```

### 6.3 `getAppOnShowParam()` 的行为

```js
// common_pure.js
const getAppOnShowParam = () => {
  if (appConfig.host == 'bd') return bus.onShowQuery  // 百度用 bus

  options = uni.getEnterOptionsSync()  // 微信/抖音/快手：调用平台 API
  // bus.clearAppShowOptions=true 时，只保留 mid/eid
  
  return { showFrom, query, path, options: { query } }
}
```

**关键行为**：`uni.getEnterOptionsSync()` 返回**最近一次进入**小程序的参数。

| 场景 | 返回的 query |
|------|------------|
| 冷启动 | 完整的启动参数 |
| 切后台回前台（微信播放器插件） | `{}` （path 为插件路径） |
| 切后台回前台（普通页面） | `{}` |

## 八、投流渠道缓存机制

### 8.1 写入缓存

`parseCoopParams` 中，投流渠道（`touliu` / `h5ad`）在以下条件下写入 `share-coop` storage：

```
条件：!share.getAndCheckAdStore(options)（没有有效缓存）
写入内容：
  {
    ...coopObj.param,
    mid 或 dramaId,
    __exp: promotion_pt / 3698 * 3600,  // 过期秒数（promotion_pt 单位为 3698 秒）
    __time: Date.now()
  }
```

### 8.2 缓存有效性检查（`getAndCheckAdStore`）

```
返回 false（不使用缓存）的条件：
  1. share.coopStore 不存在
  2. options.mid 与 coopStore.mid 不同（不同媒体）
  3. options.dramaId 与 coopStore.dramaId 不同
  4. checkAdStoreExpired() = true（已过期）

返回 coopStore（使用缓存）：
  → 同一媒体 + 未过期
  → 此时 coopObj.param 会被 adParam 完整覆盖
```

## 九、渠道变化检测

`checkIfMountChannelChanged` 在每次 `parseCoopFromParams` 后执行：

```
触发 onCoopChanged 回调的条件：
  1. coop_main 发生变化（且非首次解析）
  2. coop_client 发生变化（且非首次解析）
  3. coop_client 变为 wxchannel（视频号渠道，任何时候都触发）

触发 bus.updatePayment 的条件：
  coop_client 变化 或 promotion_ad_id 变化
  → { token: true, member: true, vod: true }（触发支付信息刷新）
```

`onCoopChanged` 回调（`App.vue`）：
```
→ 检查 CP 是否变化
  → CP 变化：onCPChanged → refreshDeliver
  → CP 不变：refreshDeliver
```

## 十、`isOfficialAccountClient()` 判断逻辑

用于识别微信公众号投流渠道（`source=h5_gzh && promotion_code=jlgg`）：

```js
isOfficialAccountClient() {
  // 第一优先级：mountParams（parseCoopParams 写入，valid=true 时才有值）
  const mountParams = vars.coopObj.mountParams || {}
  if (mountParams.source === 'h5_gzh' && mountParams.promotion_code === 'jlgg') {
    return true
  }
  // 兜底：getAppOnShowParam().query（依赖 getEnterOptionsSync，切后台后为 {}）
  const query = common.getAppOnShowParam().query
  return query.source === 'h5_gzh' && query.promotion_code === 'jlgg'
}
```

**已知问题**：`source=h5_gzh` 不满足 `mountInputIsValid` 中 `source === 'h5'` 的条件，导致 `mountParams` 始终为 `{}`，第一优先级永远不命中，只能依赖兜底逻辑。切后台后兜底逻辑也失效（query 为 `{}`）。

## 十一、`wxh5adclick` 上报

公众号投流渠道的点击回传请求，发往 `jlgg_wx/wxh5adclick`。

### 11.1 参数构造

```js
async wxh5adclick(prptChannel) {
  const launchQuery = bus.launchQuery || {};           // 冷启动原始参数
  const { promotion_ad_id, callback } = reportParam.getReportParam();
  const basicParam = {
    union_id, app_code, promotion_ad_id,
    _callback_: callback, fudid
  };
  // launchQuery 提供完整原始参数（popularizeId/microapp_id/source 等）
  // basicParam 覆盖同名字段，确保使用最新的 promotion_ad_id/callback
  const submitParams = { ...launchQuery, ...basicParam };
  this.request({ url, data: submitParams, method: 'GET' });
}
```

### 11.2 为什么用 `bus.launchQuery` 而不是 `getAppOnShowParam()`

`getAppOnShowParam()` 内部调用 `uni.getEnterOptionsSync()`，切后台回前台后返回空 query。`bus.launchQuery` 在 `onLaunch` 时写入，整个生命周期不变。
