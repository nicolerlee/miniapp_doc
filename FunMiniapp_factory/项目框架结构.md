## 1. 顶层目录

整个仓库按「前端 + 后端 + 文档」拆成 3 个一级目录：

```text
FunMiniapp_factory/
├── docs/                       # 设计文档、原型、架构说明（本文件所在处）
│   ├── project-sync-design.md
│   ├── project-sync-design-redis.md
│   ├── 项目框架结构.md         # ← 本文件
│   ├── 首页.html               # 首页原型
│   └── 小程序工厂.html         # 小程序工厂原型
├── FunMiniFactory/             # 前端工程：Vue3 + Vite（图标资源放这里）
└── FunMiniFactoryManager/      # 后端工程：Java Spring Boot
```

**约定：**

- `docs/` 只放 markdown 和 html 原型，不放可执行代码。
- 所有图标资源直接放在 `FunMiniFactory/public/icons/`，由前端唯一管理；后端不持有图标。详见 §2。
- `FunMiniFactory` 与 `FunMiniFactoryManager` 各自是一个独立 Git 子工程（已经存在 `.git` 目录），保持彼此可独立部署。

## 2. 图标资源目录（FunMiniFactory/public/icons/）

把原型 HTML 里散落的 Font Awesome 图标和 `prototypes/logos/` 下的 PNG 统一搬到前端的 `public/` 目录，按用途分桶。放在 `public/` 下的好处：

- vite 构建时**原样输出**，不参与 hash，路径稳定（线上就是 `/icons/platform/wechat.svg`）。
- 模板里直接写 `<img src="/icons/category/novel.svg">` 即可，不需要 import，原型 html 复制过来几乎不用改。
- 后端 / docs 原型如果需要引用同一份图，也用相对路径访问，避免多份拷贝走样。

```text
FunMiniFactory/
└── public/
    ├── favicon.svg
    └── icons/
        ├── platform/                # 投放平台
        │   ├── wechat.svg           # 微信小程序
        │   ├── douyin.svg           # 抖音小程序
        │   ├── kuaishou.svg         # 快手小程序
        │   ├── baidu.svg            # 百度小程序（预留）
        │   ├── alipay.svg           # 支付宝小程序（预留）
        │   └── h5.svg               # H5 / Web
        ├── category/                # 业务分类（首页侧边栏用，方案 B：H5 拆成 4 个顶级类）
        │   ├── all.svg              # 全部（fa-border-all）
        │   ├── video.svg            # 影视（fa-film）
        │   ├── drama.svg            # 短剧（fa-clapperboard）
        │   ├── comic.svg            # 漫剧（fa-masks-theater）
        │   ├── novel.svg            # 小说（fa-book）
        │   ├── h5_novel.svg         # H5 小说
        │   ├── h5_yingshi.svg       # H5 影视
        │   ├── h5_fx.svg            # H5 分销
        │   └── h5_lx.svg            # H5 拉新
        ├── brand/
        │   ├── funmini-logo.svg     # 顶部 FunMini 主 Logo
        │   └── funmini-mark.svg     # 简化版方形标
        └── ui/                      # 通用交互图标
            ├── search.svg
            ├── arrow-right.svg
            ├── chevron-left.svg
            ├── chevron-right.svg
            ├── refresh.svg          # 手动同步按钮
            ├── settings.svg
            └── user.svg
```

**为什么这么拆：**

- `platform` 与 `category` 经常一起出现在筛选条与列表行上，分桶后命名清晰，前端按 key 取图就行：`/icons/${kind}/${key}.svg`，配合一个轻封装的 `<AppIcon kind="platform" name="wechat" />` 组件即可。
- 原型现在用的是 Font Awesome CDN（`fa-brands fa-weixin` 等）。生产环境不依赖 CDN，把这些图标全部以 SVG 形式落到 `public/icons/`，构建产物里就有，自带兜底。
- `prototypes/logos/` 下已有的 PNG（`weixin_logo.png` / `douyin_logo.png` 等）保留作为**彩色版**备份；`public/icons/platform/*.svg` 用于 UI 上的小图标（单色 or 品牌主色）。

## 3. 前端工程 FunMiniFactory（Vue3 + Vite）

```text

Vue Router 4         路由
Pinia                状态管理
Tailwind CSS         原子样式（与原型保持一致）
Axios                HTTP
unplugin-auto-import 自动导入
```

> - 不上 TS，全部 `.js` / `.vue`，组件里写 `<script setup>` 即可。
> - 字段约定通过 JSDoc 注释 + `src/types/*.js` 里的常量/示例对象来对齐，IDE 也能给到基本提示。

| 原型文件 | 对应路由 | 视图组件 | 说明 |
|---|---|---|---|
| `docs/首页.html` | `/` | `HomeView.vue` | 主页，第一版唯一面向用户的页面 |
| `docs/小程序工厂.html` | `/factory` | `FactoryView.vue` | 管理子页（二期再做，第一版只占位） |

第一版只交付 `HomeView`：左侧分类筛选（全部 / 影视 / 短剧 / 漫剧 / 小说 / H5 小说 / H5 影视 / H5 分销 / H5 拉新）+ 右侧搜索 + 项目卡片列表 + 分页，所有数据来自 `/api/projects`，不放统计区块。

**和后端的接口对齐：**

```text
GET  /api/projects                   列表 + 搜索 + 筛选 + 分页
GET  /api/projects/stats             统计（按 category / platform 聚合 + 最近新增，二期使用）
GET  /api/project-sync/status        所有 source 的同步水位与状态
POST /api/project-sync/run           异步触发全部同步，返回 taskId
POST /api/project-sync/run/{source}  异步触发单个 source 同步，返回 taskId
GET  /api/project-sync/tasks/{id}    查询手动同步任务进度
```

详细字段定义见 `project-sync-design.md` §13.2。

**首页（HomeView）展示字段：**

```text
平台徽章（微信/抖音/快手/H5） / 类型标签（影视/短剧/漫剧/小说/H5）
项目名称 / APPID / 版本号 / 更新时间相对值 / 「进入」按钮
```

`/api/projects` 默认返回：

```text
appId / appName / category / platform / version / source / sourceUpdateTime / entryUrl
```

`entryUrl` 不展示成单独列，只给「进入」按钮使用。`entryUrl` **不入 `factory_app` 表**，由后端在出参时按 `source` 从 `factory-sources.yml` 取，这样新增子系统改配置即可，无需迁移历史数据。

**`factory-sources.yml` 长这样**（对应 `project-sync-design.md` §5 的 source -> baseUrl 映射，独立成文件方便加 source。`entry-url` 是 source 级跳转入口，由 Manager 在 `/api/projects` 出参时按 source 拼到 `entryUrl` 字段，**不入库**）：

```yaml
factory:
  sync:
    incremental-cron: "0 */2 * * * *"       # 每 2 分钟
    reconcile-cron:   "0 0 3 * * *"         # 每天凌晨 3 点
    page-size: 500
    sources:
      - key: novel_miniapp
        name: 小说小程序
        base-url: http://172.17.7.183:8080/miniapp/novel
        entry-url: http://172.17.7.183:8080/miniapp/novel/home
        category-default: novel
      - key: drama_miniapp
        name: 短剧小程序
        base-url: http://172.17.7.183:8099
        entry-url: http://172.17.7.183:5177/apps
        category-default: drama
      - key: comic_miniapp
        name: 漫剧小程序
        base-url: http://172.17.7.183:8099
        entry-url: http://172.17.7.183:5177/apps
        category-default: comic
      - key: video_miniapp
        name: 影视小程序
        base-url: http://172.17.7.183:8090
        entry-url: http://172.17.7.183:8080/miniapp/autocreate/video/apps
        category-default: video
      - key: h5
        name: H5
        base-url: http://172.17.3.118:8080
        entry-url: http://172.17.3.118/h5novelwebconfig/
        # H5 子系统接口必须在 OpenAppItem.category 里返回 h5_novel / h5_yingshi / h5_fx / h5_lx 之一，不接受兜底值
        category-allowed:
          - h5_novel
          - h5_yingshi
          - h5_fx
          - h5_lx
```

**`category-default` vs `category-allowed`**：

- `category-default`：单一 category 的 source 用。子系统接口里 `category` 字段允许为空，Manager 入库时用这个兜底值。
- `category-allowed`：多 category 的 source 用（目前只有 `h5`）。子系统接口必须返回明确的 `category`，Manager 校验在白名单内才入库；返回的值不在白名单内的项目记 warn 日志并跳过。
- 两者互斥：每个 source 只能配其中一个。

**关键约束（来自 `project-sync-design.md`，落地时务必遵守）：**

- 写入 `factory_app` 必须用 `event.changeId > last_change_id` 做幂等门槛（§7.1）。
- 全量同步用第一页拿到的 `snapshotChangeId` 推进水位，**不要**用结束时的 `maxChangeId`（§5.1 / §8.1）。
- 同一 source 同一时刻只能跑一个同步任务，单实例用 JVM 锁（`ConcurrentHashMap<String, Lock>`），多实例上 Redis 锁（§11）。
- 手动同步必须异步执行，`POST /api/project-sync/run*` 只返回 `taskId`，任务状态走 `GET /api/project-sync/tasks/{taskId}`。
- 列表接口默认隐藏 `appToken / sourcePath / buildCmd / artifactDir`，需要时单独走管理接口 + 权限（§10）。
- 当前先认为各子系统已经提供全量和增量 open API，登录态和旧接口适配暂不纳入本轮设计。

## 5. 数据库设计

直接采用 `project-sync-design.md` 已经定稿的方案，不再重复贴 SQL。简述：

| 表 | 归属 | 作用 |
|---|---|---|
| `factory_app` | FunMiniFactoryManager 中央库 | 项目目录主表，前端列表/统计直接读 |
| `factory_app_sync` | FunMiniFactoryManager 中央库 | 每个 source 一行的同步水位表 |
| `app_change_log` | 各子系统自己的库 | 子系统的变更流水，由 `/api/open/apps/updates` 暴露 |

第一版只在 FunMiniFactoryManager 侧维护两张表，子系统的 `app_change_log` 由各业务团队按 §6 的 schema 自建。

## 8. 命名与代码风格速记

- **包名**：`com.funshion.funminifactory.{config|domain|service|...}`，避免和现有 `FunMiniappManagerServer` 串味。
- **source key**：snake_case，统一使用 `novel_miniapp / drama_miniapp / comic_miniapp / video_miniapp / h5`。H5 是单一 source，但要在接口返回里把 `category` 区分成 `h5_novel / h5_yingshi / h5_fx / h5_lx`。
- **枚举**：Java 端首字母大写（`Category.NOVEL`），DB / API 层用小写字符串，进出口在 `enums` 包内统一转换。
- **前端组件**：PascalCase 文件名（`ProjectRow.vue`），composable 用 `useXxx.js`。所有 `.vue` 文件里 `<script setup>` 不带 `lang="ts"`。
- **图标 key**：`platform/wechat`、`category/novel`，前端 `AppIcon` 组件按 `kind="platform" name="wechat"` 拼成 `/icons/platform/wechat.svg`。
